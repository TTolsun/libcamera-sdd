# 요청 완료 상태와 버퍼 수명 판단의 대표 사례

[대표 문서](https://ttolsun.github.io/libcamera-sdd/request-lifecycle.html#요청버퍼fence의-수명)는 제출 성공·버퍼 알림·내부 완료 상태·애플리케이션 반환·핸들러 접근 종료를 구분합니다. 새 페이지를 늘리지 않고 기존 수명 항목을 문제 → 원리 → 정상 흐름 → 조건 변화·실패 → 변경 확인으로 구성했습니다. 공통 생성 계약은 [생성기 PR #259](https://github.com/TTolsun/camera-hal-sdd-generator/pull/259)와 [통합 보정 PR #268](https://github.com/TTolsun/camera-hal-sdd-generator/pull/268)에 병합됐습니다. 배포 실행과 실제 공개 URL 대조 결과는 [이슈 #249](https://github.com/TTolsun/camera-hal-sdd-generator/issues/249)의 발행 댓글을 확인하세요.

## 새로 확인한 판단

사전에 고정한 다섯 질문을 작성 맥락 없는 별도 Codex CLI가 문서만 읽고 풀었습니다. 별도 채점 결과는 기준본 **4/5**, 개선본 **5/5**입니다. 기준본에서 미발견이었던 B의 내부 완료 상태를 개선본 독자는 `cancelled_`가 false이면 `RequestComplete`, true이면 `RequestCancelled`로 구분했습니다. 플래그가 주어지지 않았으므로 버퍼 처리가 끝났다는 사실만으로 한 상태를 확정하지 않았습니다.

이 상태 선택과 반환 시점은 별개입니다. 매번 큐 선두를 다시 검사하므로 중간 Pending 요청이 있으면 A가 끝났다는 사실만으로 B 반환을 보장하지 않습니다. 핸들러의 완료 함수 반환 뒤 접근 금지와 호출자의 요청 완료 콜백까지 버퍼 유효성 의무도 다른 경계입니다. 정상 흐름·버퍼 알림·취소·변경의 나머지 네 과업은 기준본도 통과했으므로 새로 획득한 능력으로 세지 않았습니다.

최초 2/5 대 5/5 비교는 질문 밖 API 상세·식별자 철자까지 요구한 채점 문제로 제외했습니다. 질문을 바꾸지 않고 양쪽에 같은 기준을 적용했을 때 중간 개선본도 취소 플래그의 참 분기를 놓쳐 4/5였습니다. 그 미발견을 실제 구현 창과 본문·그림으로 보완하고 다시 읽게 했습니다. 실패 초안·원본 채점표·수정표·실제 호출은 모두 보존했습니다. 이는 실제 사람의 이해도나 통계적 효과를 측정한 결과가 아닙니다.

## 검증과 보존

- 대표 항목의 본문·그림·조건부 예는 13개 고정 소스 창에 대한 독립 Codex CLI / `gpt-6.1-terra` / high 검토를 통과했습니다. 설계 의도·대안 우열·실기기 보장은 추정하지 않았습니다.
- 같은 입력의 검증된 원고 재사용은 새 모델 호출 없이 답변·근거·그림을 보존했습니다. 새 LLM 표본의 문장이 항상 같다는 뜻은 아닙니다. 질문·소스·단계 변경의 입력 지문 무효화도 회귀로 검사했습니다.
- 생성기 최종 CI는 Linux 3.11·3.14 각각 2,961개 통과, Windows 3.11·3.14 각각 2,960개 통과·1개 생략입니다. 최신 main 통합 회귀 322개도 통과했습니다. 병합 트리의 코드·시험·대표 설정은 검증한 헤드와 같습니다.
- 두 번의 정상 export에서 manifest와 350개 산출물이 같고, 66페이지의 내부 링크 오류는 0개입니다. 기준 산출물 삭제는 0개이며 대표 항목 밖 Mermaid 156개는 바이트가 같습니다. 배포 전 누락을 발견한 공식 cam 그림 여섯 개는 원래 공개 정의로 복원했습니다.
- 한영 데스크톱·모바일의 그림 렌더링, 초기 읽기 글자 크기, 확대·검색·닫기·초점 복원과 근거 펼침·설명 복귀를 Chrome으로 확인합니다. 이 결과는 기기 실행 검증이 아닙니다.
- 새 전체 계약 대조는 모순 없이 통과했지만, 대표 항목 밖의 기존 문장에 대한 모호함·근거 부족 판정 8개를 보존했습니다. 오류 8건을 확정한 수치가 아닙니다. 오류 검사 순서, 조사 안내의 실행 여부, 일반 완료와 취소의 의무 범위, 기본 인자 발췌 부족이 남아 있습니다. 사이트 전체의 의미 승인을 뜻하지 않습니다.

공개 #250의 독자 경로·용어·그림과 #241의 별도 검증 하위 사이트도 보존했습니다. 다만 장치 해제와 소멸이 혼동되던 #250의 소유권 그림 하나는 실제 CLI로 재생성하고 두 소스 창의 독립 검토를 통과했습니다. 한영 변경 111단위의 전체 검토 뒤 남은 두 수정 단위를 새로 검토하고 나머지 109단위의 바이트·맥락·표시를 대조했습니다. 이전 검토의 미통과 결과도 그대로 보존했습니다.

공개 #243의 최신 원고·두 그림·원래 인증 프로필과 #248의 독자 질문 라벨·영어 보정도 보존했습니다. 원래 생성자·날짜·과거 소스와 사람 검토 전 상태를 현재 CLI의 새 생성으로 바꾸지 않았습니다. 저장 응답·직접 API·다른 CLI를 새 재현 성공으로 사용하지 않았습니다. 병렬 검토도 같은 CLI·표준 검증·원본 영수증·체크포인트를 사용했고 마지막 표준 `audit-consistency`가 전체를 재검증했습니다.

## 입력과 분량

분석 기준과 공개 upstream mirror는 `be7e83e91348250c015aad6d6f59f1468555bae8`입니다. 실제 Meson/Ninja 빌드와 Clang 추출은 294개 번역 단위, 파싱 오류 0개, 10개 파이프라인·7개 IPA·6개 시나리오를 포함합니다. 클래스 1,412개에서 1,403개로 바뀐 차이는 LC-compliance 테스트 도구의 다섯 번역 단위 제외이며 소스 삭제가 아닙니다. 원래 가상 CPU 프로브는 `293d751a…`의 과거 기록으로 유지했고 재실행하지 않았습니다.

새 대표 항목의 원래 생성 소스는 `293d751a…`입니다. 실제 근거 파일의 바이트가 최신 커밋과 같고 모든 인용·선택 창을 최신 facts에서 다시 검증했음을 별도로 기록합니다. 실제 기기·DMA·캐시·시간과 사내 HAL, 사람의 이해도는 검증하지 않았습니다. 실제 사람 결과가 없는 동안 이슈와 Goal 전체를 완료로 표시하지 않습니다.

렌더러가 붙인 인용·원문·제목·그림·메타데이터를 제외한 답변 텍스트 기준으로, 대표 항목은 1,298자에서 3,168자, 페이지 전체는 7,503자에서 8,582자로 바뀌었습니다. 제출·정지 항목의 반복 답변을 통합해 전체 순증은 1,079자입니다. 분량 증가 자체를 성과 점수로 쓰지 않습니다. 자세한 선택·이동 이유는 `before-after.json`과 원고의 `integration_lineage`에 있습니다.

## 원본과 재현

`native-and-operation-evidence.tar.xz`와 `archive-index.json`은 기준·최종 원고, 실제 CLI 요청·응답·stdout·영수증, 실패·미완료 기록, 고정 질문·채점표, 실제 소스 창·facts·빌드 입력, 유효 설정·집필 규칙·검토 결과를 묶습니다. `package.json`이 archive와 색인의 해시를 고정합니다. `native-call-verification.json`은 실제 완료된 원본 438건을 검증하며, 이전 실패·교체된 초안의 호출도 포함한 전체 작업 기록입니다. 승인된 최종 호출 438건이라는 뜻이 아닙니다. CLI 초기화의 Windows 접근 거부와 중단한 실행은 성공으로 세지 않았습니다. pytest 대역은 이 검증·archive에서 제외했습니다.

원래 경로·모델·인자를 보존했습니다. 다른 환경에서는 archive의 입력 색인에 따라 경로를 명시적으로 재배치해야 합니다. 읽기 평가는 생성기의 `examples/libcamera/validation/issue249/evaluate.py`, 별도 채점은 `grade.py`, 독립 검토 설정은 `independent-review.yaml`을 사용합니다. 원고·그림의 과거 프로필과 원본 영수증을 현재 값으로 다시 쓰지 마세요.

절차·전후 수치·보존 여부는 표와 원본 기록으로 비교할 수 있으므로 이 발행 기록에는 별도 그림을 반복하지 않았습니다.
