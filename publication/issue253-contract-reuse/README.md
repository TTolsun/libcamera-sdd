# 계약 검토의 증분 갱신 비용

공개 libcamera의 qcam 자동 화이트 밸런스 변경 한 건을 비교했습니다. 부모는 `be909e49…`, 변경본은 `293d751a…`입니다. 파일 2개에서 10줄이 바뀌었고, 문서 28개의 본문을 승계했으며 구성 요소 색인 1개를 다시 만들었습니다. 측정 전에 기존 facts·원고·한영 카탈로그와 검토 정책, 88개 배치의 대상·비교 주장·근거를 고정했습니다.

기존 실험은 부모와 변경본의 검토 캐시를 각각 비운 디렉터리에서 시작했습니다. 두 캐시를 공유하더라도 요청과 키에 소스 전체의 SHA가 들어가 88개가 모두 달라졌습니다. 그중 20개는 시나리오 분석 근거 안에 중복 기록된 SHA도 달라졌습니다. 두 SHA를 제외하면 88개 배치의 문장·비교 주장·인용 위치·발췌 내용은 같았습니다.

| 단계 | 신규 Codex CLI 호출 | 재검증한 원본 영수증 | 기계 경과 시간 |
| --- | ---: | ---: | ---: |
| 새 정책으로 부모 캐시 구성, 동시 4개 | 88 | — | 651.05초 |
| 부모 정상 감사 | 0 | 88 | 9.82초 |
| 원본 프롬프트와 체크포인트 복사 | 0 | — | 0.38초 |
| 변경본 정상 감사 | 0 | 88 | 10.51초 |

현재 원고와 근거의 출처를 확인하고, 최상위 SHA만 정규화한 검토 입력이 일치할 때 기존 결과를 사용했습니다. 당시 SHA가 들어간 실제 요청과 원본 영수증은 그대로 검증했습니다. 두 정상 감사 모두 과거 영문 원고에서 같은 모순 1건과 미판정 3건을 확인했습니다. 게시 검사는 모순 때문에 두 실험본을 모두 차단했습니다. 모순이 있었던 문장은 요청의 버퍼와 매개변수 집합 모두에 스트림 연결이 있다고 읽혔습니다. 실험 후속 공개본은 버퍼가 각각 스트림과 연결된다는 문장과 매개변수 집합을 설명하는 문장을 분리했습니다.

이 수치는 전체 갱신 시간이 아니라 계약 감사와 캐시 준비 비용입니다. 최초 검토, 정책·모델·검토 설정 변경, 원본 영수증 부재, 또는 실제 검토 입력 변경에는 새 호출이 필요합니다. 이전 순차 실행과 이번 병렬 실행의 경과 시간을 일반 절감률로 환산하지 않았습니다. 비용 표본은 소스 변경 한 건입니다. 사람 참가자는 0명이며 사람 검토 시간과 독자 부담은 측정하지 않았습니다. #253과 #163의 사람 평가는 미완료입니다.
