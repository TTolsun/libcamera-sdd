클래스별 책임

CameraManager는 libcamera의 진입점으로, 시스템의 장치를 열거하고 애플리케이션에 카메라 접근을 제공하며 카메라 객체의 수명을 관리합니다. 한 번에 단일 CameraManager 인스턴스만 존재할 수 있으며, 기존 인스턴스를 삭제하기 전에 추가 인스턴스를 만들면 동작이 정의되지 않습니다.

Camera 클래스는 하나의 이미지 소스에서 하나 이상의 이미지 스트림을 생성하는 카메라를 모델링하며, 장치의 설정과 제어, 이미지 스트림 캡처를 위한 주요 인터페이스를 제공합니다. libcamera는 std::shared_ptr<>로 Camera 인스턴스의 수명을 관리합니다. 인스턴스는 std::shared_ptr을 반환하는 create() 함수로 생성해야 하며, Camera의 생성자와 소멸자는 비공개이므로 인스턴스를 수동으로 생성하거나 소멸하는 것을 막습니다. Request는 애플리케이션이 프레임마다 버퍼와 컨트롤을 연결해 장치 처리를 위해 큐에 넣을 수 있게 하는 프레임 캡처 요청 객체입니다.

Request 생성자에 전달한 cookie는 요청에 저장되는 애플리케이션용 불투명 값이며, cookie() 함수로 언제든지 읽을 수 있습니다.

상태와 허용 호출

Camera의 상태 다이어그램에서 acquire()는 Available 상태를 Acquired 상태로 바꿉니다. Acquired 상태에서 configure()를 호출하면 Configured 상태로, release()를 호출하면 Available 상태로 전이합니다. 다이어그램에 나오지만 이 상태에서 전이가 없는 연산은 허용되지 않으며, 허용되지 않은 연산을 수행하면 정의되지 않은 동작이 발생합니다. 다이어그램에 전혀 나오지 않는 연산은 모든 상태에서 허용됩니다.

Camera::configure()는 d->isAccessAllowed(Private::CameraAcquired, Private::CameraConfigured)가 음수이면 그 값을 반환하고, config->validate()가 CameraConfiguration::Valid가 아니면 LOG(Camera, Error)를 출력한 뒤 -EINVAL을 반환합니다. pipe_->invokeMethod(&PipelineHandler::configure, ...)가 0이 아닌 값을 반환하면 그 값을 그대로 반환하고, 설정 후 어떤 cfg.stream()이 null이면 LOG(Camera, Fatal)을 출력하고 activeStreams_를 비운 뒤 return -EINVAL;을 실행하는 분기가 있으며, LOG 문서에 따르면 Fatal은 메시지 출력 후 프로그램을 종료합니다. 모든 스트림 검사를 통과하면 d->setState(Private::CameraConfigured)로 상태를 Configured로 설정하고 0을 반환합니다.

상태 다이어그램에서 Configured 상태의 start()는 카메라를 Running 상태로 이동시키는 전이로 표시됩니다. 다이어그램은 start()의 성공과 실패를 구분하지 않으므로, 성공 조건은 이 소스만으로 확인할 수 없습니다.

상태 다이어그램에서 Running 상태의 stop() 전이는 Stopping 상태로 이어집니다. 따라서 Running 상태의 카메라에 stop()을 호출하면 Stopping 상태에 진입합니다. 다이어그램상 Stopping 상태는 Configured 상태로 이어집니다.

정지 처리가 끝난 뒤 카메라가 돌아가는 상태는 Configured입니다. 상태 다이어그램에서 Stopping에서 Configured로 가는 화살표가 이 복귀를 나타내며, 이 화살표에는 호출 이름이 표시되어 있지 않습니다. 따라서 이 인용만으로는 어떤 함수 호출이 이 복귀를 일으키는지 확인할 수 없습니다. release()는 Available 상태에서 호출하면 상태가 그대로 Available로 남고, Acquired 또는 Configured 상태에서 호출하면 상태가 Available로 바뀝니다.

호출자는 카메라가 Configured 또는 Running 상태일 때에만 createRequest를 호출할 수 있습니다. 이 두 상태는 camera_operation에서 정의된 상태를 가리킵니다.

Camera::queueRequest는 카메라가 camera_operation에서 정의한 Running 상태일 때만 호출할 수 있습니다. 카메라가 실행 중이 아니면 queueRequest는 -EACCES를 반환하며, 요청은 큐에 들어가지 않습니다. 이 호출 조건은 queueRequest에 대한 설명이며, 다른 함수의 조건과 함께 묶어 해석하지 않습니다.

Camera::start는 카메라가 Configured 상태에 있을 때만 호출할 수 있습니다. start의 반환값 중 -EACCES는 카메라가 시작할 수 있는 상태가 아님을 나타냅니다. Camera 클래스는 아래에서 정의하는 카메라 상태에 영향을 주는 함수들을 일반적으로 서로 동기화하지 않습니다. 동기화가 필요한 경우 호출자가 그 동기화를 보장해야 합니다.

오류와 종료

Camera::queueRequest()는 먼저 d->isAccessAllowed(Private::CameraRunning)를 호출합니다. 이 결과가 음수이면 ret 값을 그대로 반환하고, 음수가 아니면 다음 검사로 넘어갑니다. 주석에 나열된 -ENOMEM에 대응하는 반환 분기는 발췌 본문에서 보이지 않습니다.

request->_d()->camera()가 this와 다르면 queueRequest()는 LOG를 남기고 -EXDEV를 반환합니다. 주석대로 요청은 이를 생성한 카메라에만 큐잉할 수 있습니다. request->status()가 Request::RequestPending과 같지 않으면 LOG를 남기고 -EINVAL을 반환합니다. 이 검사는 controls 검사보다 먼저 수행됩니다.

request->controls().infoMap()이 &controls()와 다르면 LOG를 남기고 -EINVAL을 반환합니다. 로그 문구는 Overwriting Request::controls() is not allowed입니다. request->buffers()가 비어 있으면 -EINVAL을 반환하며, 이 검사는 스트림 검사보다 먼저 수행됩니다. 이어서 요청 버퍼의 각 stream이 d->activeStreams_에 없으면 -EINVAL을 반환합니다.

위 검사를 모두 통과하면 patchControlList(request->controls())로 AeEnable을 전처리한 뒤, d->pipe_->invokeMethod(&PipelineHandler::queueRequest, ConnectionTypeQueued, request)를 호출하고 0을 반환합니다. 촬영 완료는 주석에 따라 requestCompleted signal로 알려집니다.

Camera::stop()은 d->isRunning()이 거짓이면 상태를 바꾸지 않고 0을 반환합니다. 실행 중이면 d->isAccessAllowed(Private::CameraRunning)의 음수 결과를 그대로 반환합니다. 따라서 주석의 -EACCES와 달리 실행 중이 아닐 때는 오류가 아닌 0이 반환됩니다.

실행 중이면 d->setState(Private::CameraStopping)으로 상태를 바꾼 뒤 d->pipe_->invokeMethod(&PipelineHandler::stop, ConnectionTypeBlocking, this)를 호출합니다. 이어서 ASSERT(!d->pipe_->hasPendingRequests(this))로 대기 요청이 없음을 확인하고, d->setState(Private::CameraConfigured) 뒤 0을 반환합니다. API 주석은 대기 요청이 취소되어 오류 상태로 동기 완료된다고 설명하지만, 이 발췌 본문에는 취소 처리 코드가 보이지 않습니다.

동시성과 실행 확인

Camera::createRequest() 함수의 주석은 이 함수를 threadsafe로 명시합니다. 이 내용은 주석에 기술된 문서상의 보장입니다. 발췌된 원문에는 함수 본문이 없으므로 구현에서 이를 확인한 것은 아닙니다. queueRequest의 주석은 이 함수가 threadsafe하다고 명시합니다.

Camera::start의 context 주석은 호출자가 카메라 상태에 영향을 주는 다른 함수와 동기화해야 한다고 명시합니다. Camera::stop의 context 주석도 같은 범위의 동기화 의무를 호출자에게 명시합니다. 따라서 호출자는 start와 stop 호출을 카메라 상태에 영향을 주는 다른 함수들과 동기화해야 합니다.

completeRequest()를 호출하는 파이프라인 핸들러는 CameraManager 스레드에서 호출해야 합니다. 이 함수의 \context 항목은 호출 스레드를 CameraManager 스레드로 명시하며, 이는 호출하는 쪽이 지켜야 하는 조건입니다. 이 주석은 애플리케이션 콜백이 실행되는 스레드를 명시하지 않습니다. Camera::requestComplete()는 완료된 request를 requestCompleted.emit(request)에 넘겨 requestCompleted 신호를 발행합니다.

연결 해제와 대기 요청

Camera::Private::disconnect()는 state_가 CameraRunning일 때만 CameraConfigured로 상태를 저장하고, 다른 상태에서는 이 저장을 생략합니다. 그와 별도로 disconnected_는 상태와 관계없이 항상 true로 설정됩니다. 주석에 따르면 이 처리의 목적은 카메라를 삭제하기 전에 애플리케이션이 자원을 해제하고 release()를 호출할 수 있도록 하는 것입니다.

Camera::Private::isAccessAllowed의 두 오버로드는 !allowDisconnected와 disconnected_가 모두 참이면 상태를 확인하기 전에 -ENODEV를 반환합니다. 단일 state 오버로드는 currentState가 state와 같으면 0을, 범위 오버로드는 currentState가 low와 high 사이에 있으면 0을 반환합니다. 그 외의 경우에는 오류 로그를 출력한 뒤 -EACCES를 반환하며, 로그에서 from은 호출 함수 이름으로 () requiring state 앞에 출력됩니다. 로그의 Camera in 뒤 상태 이름은 두 오버로드 모두 currentState에서 가져오고, 요구 상태 이름은 단일 오버로드에서 state, 범위 오버로드에서 low와 high에서 가져옵니다.

Camera::disconnect()는 _d()->disconnect()를 먼저 호출한 뒤 disconnected.emit()를 호출합니다. 두 호출은 소스에 적힌 순서대로 실행되므로, disconnected 시그널은 _d()->disconnect() 호출이 끝난 뒤에 방출됩니다.

\brief Queue a request to the camera
 * \param[in] request The request to queue to the camera
 *
 * This function queues a \a request to the camera for capture.
 *
 * After allocating the request with createRequest(), the application shall
 * fill it with at least one capture buffer before queuing it. Requests that
 * contain no buffers are invalid and are rejected without being queued.
 *
 * Once the request has been queued, the camera will notify its completion
 * through the \ref requestCompleted signal.
 *
 * \context This function is \threadsafe. It may only be called when the camera
 * is in the Running state as defined in \ref camera_operation.
 *
 * \return 0 on success or a negative error code otherwise
 * \retval -ENODEV The camera has been disconnected from the system
 * \retval -EACCES The camera is not running so requests can't be queued
 * \retval -EXDEV The request does not belong to this camera
 * \retval -EINVAL The request is invalid
 * \retval -ENOMEM No buffer memory was available to handle the request
 */
int Camera::queueRequest(Request *request)
{
    Private *const d = _d();

    int ret = d->isAccessAllowed(Private::CameraRunning);
    if (ret < 0)
        return ret;

    /* Requests can only be queued to the camera that created them. */
    if (request->_d()->camera() != this) {
        LOG(Camera, Error) << "Request was not created by this camera";
        return -EXDEV;
    }

    if (request->status() != Request::RequestPending) {
        LOG(Camera, Error) << request->toString() << " is not valid";
        return -EINVAL;
    }

    /* Make sure the Request has a valid control list. */
    if (request->controls().infoMap() != &controls()) {
        LOG(Camera, Error) << "Overwriting Request::controls() is not allowed";
        return -EINVAL;
    }

    /*
     * The camera state may change until the end of the function. No locking
     * is however needed as PipelineHandler::queueRequest() will handle
     * this.
     */

    if (request->buffers().empty()) {
        LOG(Camera, Error) << "Request contains no buffers";
        return -EINVAL;
    }

    for (const auto &[stream, buffer] : request->buffers()) {
        if (d->activeStreams_.find(stream) == d->activeStreams_.end()) {
            LOG(Camera, Error) << "Invalid request";
            return -EINVAL;
        }
    }

    /* Pre-process AeEnable. */
    patchControlList(request->controls());

    d->pipe_->invokeMethod(&PipelineHandler::queueRequest,
                   ConnectionTypeQueued, request);

    return 0;
}

void Camera::Private::disconnect()
{
    /*
     * If the camera was running when the hardware was removed force the
     * state to Configured state to allow applications to free resources
     * and call release() before deleting the camera.
     */
    if (state_.load(std::memory_order_acquire) == Private::CameraRunning)
        state_.store(Private::CameraConfigured, std::memory_order_release);

    disconnected_ = true;
