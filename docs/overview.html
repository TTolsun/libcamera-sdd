이 문서의 용어: IPA, Pipeline Handler
  • IPA (Image Processing Algorithms): 화질 알고리즘을 담은 별도 모듈(.so)입니다. ISP가 보낸 통계를 보고 다음 프레임에 쓸 ISP 설정값을 계산합니다. 제조사가 소스를 공개하지 않고 제공할 수 있도록 libcamera 본체와 분리되어 있습니다.
  • Pipeline Handler: 특정 하드웨어 플랫폼(IPU3, RKISP1 등)의 미디어 장치를 찾아 카메라를 만들고, 요청을 장치에 넣고 완료를 돌려주는 libcamera 구성 요소입니다. 플랫폼마다 하나씩 있습니다.

다른 용어는 용어집에서 찾을 수 있습니다.

탐색과 파이프라인 선택

CameraManager는 libcamera의 진입점으로, 장치를 열거하고 파이프라인과 연결하며 애플리케이션이 시스템의 카메라에 접근하도록 합니다. CameraManager::Private::pipelineFactoryMatch()는 팩토리에서 PipelineHandler를 만들고 열거된 장치와 일치하는지 확인합니다. 일치하는 파이프라인을 최대한 제공하도록 이 과정을 반복하며, match()가 거짓을 반환하면 반복을 끝냅니다.

CameraManager 인스턴스는 동시에 하나만 존재해야 합니다. 기존 인스턴스를 먼저 삭제하지 않고 두 번째 인스턴스를 생성하면 동작이 정의되지 않습니다. CameraManager::start()의 시작이 확인되면 애플리케이션은 카메라 관리자가 중지되거나 해당 카메라가 시스템에서 분리될 때까지 시스템의 카메라를 나열하고 사용할 수 있습니다. 호출자는 CameraManager::cameras()와 CameraManager::get()을 호출하기 전에 카메라 매니저가 실행 중인지 확인해야 합니다.

PipelineHandler::match() 구현자는 필요한 미디어 장치를 모두 찾으면 MediaDevice::acquire()로 모두 획득하고, 해당 Camera 인스턴스를 생성해 내부에 저장하고 카메라 관리자에 등록한 뒤 true를 반환해야 합니다. 장치를 모두 찾지 못하면 match() 구현자는 어떤 미디어 장치도 획득하지 않거나 이미 획득한 장치를 MediaDevice::release()로 모두 해제하고 false를 반환해야 합니다.

컴포넌트별 책임

Camera는 하나의 이미지 소스에서 하나 이상의 이미지 스트림을 생성할 수 있는 카메라를 모델링합니다. 장치 구성과 제어, 이미지 스트림 캡처를 위한 주 인터페이스이며, libcamera가 공개하는 중심 객체입니다. libcamera는 카메라 인스턴스의 수명을 std::shared_ptr<>로 관리하며, 인스턴스는 공유 포인터를 반환하는 create()로 생성해야 합니다. Camera의 생성자와 소멸자는 비공개이므로 인스턴스를 수동으로 생성하거나 파괴할 수 없습니다.

요청 생성과 소유권

Camera::createRequest(cookie)의 cookie는 애플리케이션에서 사용하는 불투명한 입력값입니다. 이 값은 요청에 저장되며 Request::cookie()로 언제든 읽을 수 있습니다. 이 값은 libcamera 관점에서 완전히 불투명합니다. Camera::createRequest()는 카메라가 Configured 또는 Running 상태일 때만 호출할 수 있으며, 오류가 발생하면 nullptr을 반환합니다.
