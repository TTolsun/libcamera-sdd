카메라 API부터 Pipeline Handler와 IPA까지, 코드 구조와 근거를 함께 읽는 문서입니다.

이 문서는 공개 libcamera 소스를 분석해 만든 검토용 설계 문서입니다. libcamera 공식 문서의 탐색 구조와 OMM의 읽기 중심 디자인을 적용했습니다.

읽는 순서

먼저 카메라와 요청 모델에서 공개 API의 선언을 확인하세요. Pipeline Handler에서는 공통 클래스와 하드웨어별 구현의 관계를, IPA 관리와 구현 진입점에서는 알고리즘 모듈의 관리 구조를 살펴볼 수 있습니다.

각 페이지에는 추출한 클래스, 구조 설명, 관계 그림과 코드 근거가 있습니다. 관계 그림을 누르면 확대하거나 클래스 이름을 검색할 수 있습니다. 소스 링크는 분석에 사용한 커밋의 파일과 줄로 연결됩니다.

검토 상태 읽기

모든 생성 문서는 사람 검토 전입니다. ok는 자동 인용 검사를 통과했다는 뜻이며, 설명의 정확성이 승인되었다는 뜻은 아닙니다. needs-review는 인용 검사에서도 확인할 문제가 남아 있다는 뜻입니다.

카메라와 요청 모델에는 인용 형식 문제가 남아 있습니다. Pipeline Handler와 IPA 문서도 문장 품질과 동작 설명을 검토해야 합니다. 그림은 정적으로 추출한 상속·필드 관계를 보여 주며 실행 순서나 실기기 동작을 보증하지 않습니다.

분석과 배포 범위

분석 기준은 libcamera 커밋 279d355ef8f7a4f98bb0a3004c0f788387814506입니다. WSL2에서 IPU3·RKISP1·UVC와 GStreamer를 포함해 빌드했고, 문장은 Windows의 로컬 Ollama로 생성했습니다. 실기기 촬영과 전체 캡처 시나리오 검증은 후속 작업입니다.

camera-hal-sdd는 분석·생성·검증·화면 구성 기술을 관리합니다. libcamera-sdd는 원본 소스 이력과 완성 문서의 배포를 담당합니다. 자동 갱신 작업은 아직 연결하지 않았습니다.

원래 라이브러리의 사용법은 libcamera 공식 문서에서 확인할 수 있습니다.
