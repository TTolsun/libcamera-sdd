실제 DMA-BUF로 공식 cam의 가상 캡처를 확인한 조건과 관찰 범위를 확인하세요.

이 문서의 용어: WSL, WSL2, UDMABUF, errno 외 9개
  • WSL (Windows Subsystem for Linux): Windows의 기능으로, Windows 컴퓨터에서 Linux 환경을 실행할 수 있게 해 줍니다.
  • WSL2 (Windows Subsystem for Linux 2): Windows에서 Linux를 실행하는 환경입니다. 이 사이트는 libcamera를 WSL2에서 빌드하고 추출한 결과로 만듭니다.
  • UDMABUF (userspace dmabuf misc driver): Linux 커널의 드라이버 이름으로, 사용자 공간의 memfd 영역을 dma-buf로 바꿔 주는 드라이버입니다.
  • errno: Linux 함수가 실패 원인을 알리는 표준 오류 번호입니다. libcamera 함수는 이 값을 음수로 돌려줍니다. 예를 들어 -ENODEV는 장치 없음, -EACCES는 접근 거부, -EINVAL은 잘못된 인자, -ENOMEM은 메모리 부족, -EXDEV는 다른 객체에 속한 자원을 뜻합니다.
  • GDB (GNU Project Debugger): 지정한 조건에서 프로그램을 멈추게 하고, 멈춘 뒤 실행 상태를 살펴볼 수 있는 GNU 디버거입니다.
  • DMA (Direct Memory Access): DMA(Direct Memory Access)는 I/O 장치가 시스템 메모리를 직접 읽거나 쓰는 방식을 뜻하는 용어입니다.
  • HAL (Hardware Abstraction Layer): 운영체제가 제조사마다 다른 하드웨어를 같은 인터페이스로 다루게 하는 계층입니다. 이 프로젝트의 최종 적용 대상은 사내 Android Camera HAL입니다.
  • Pending: 아직 완료 또는 취소로 바뀌지 않은 요청 상태입니다. 장치 처리가 시작됐다는 뜻은 아니며, 앞 요청이 이 상태이면 뒤 요청의 반환도 대기할 수 있습니다.
  • TID (Linux thread ID): TID는 gettid 시스템 호출이 반환하는 Linux 스레드 ID입니다.
  • NV12 (NV12): 성분당 8비트를 쓰는 4:2:0 포맷입니다. 첫 번째 평면은 휘도(Y)이고, 두 번째 평면에는 Cb와 Cr 값이 한 개씩 번갈아 저장되는 교차 색차 데이터가 들어 있으며, 전체가 선형으로 연속된 메모리에 놓입니다.
  • GCC (GNU Compiler Collection): C, C++ 등의 프론트엔드를 포함하는 GNU 컴파일러 모음입니다.
  • VM (Virtual Machine (가상 머신)): 가상 머신은 물리 컴퓨터의 자원을 가상화하여 소프트웨어로 구현한 컴퓨터이며, 자체 운영체제와 응용 프로그램을 실행합니다. 클라우드 서버에만 해당하지 않으며 개인용 물리 컴퓨터에서도 만들 수 있습니다.
  • PR (Pull Request): 코드 변경 사항을 프로젝트에 병합해 달라고 제안하는 요청입니다.

다른 용어는 용어집에서 찾을 수 있습니다.

공식 cam과 실제 DMA-BUF 확인 결과

가상 시험 구성입니다. 실제 제품의 지원·성능 주장으로 사용하지 마세요.

udmabuf이 내장된 WSL2 시험 커널 6.18.33.2-microsoft-standard-WSL2-issue211에서 소스 293d751a814e0d4c34e85ad457ccd9d5eefd1a61 기준의 수정하지 않은 공식 cam을 root 자식 프로세스로 실행했습니다. 가상 카메라 Virtual2에 (0) 400x300-NV12/SMPTE170M 설정을 적용했고, 독립된 세 프로세스가 각각 3프레임을 완료하고 종료 코드 0으로 끝났습니다. 취소된 콜백은 세 프로세스 모두 0개였으며, 비특권 실행은 errno 13으로 실패했습니다.

DMA-BUF 접근 기록은 공식 cam이 아니라 별도 프로브 dmabuf-probe-2에서 나온 것입니다. 프로브는 allocate에서 backing_fd 4, dmabuf_fd 5, 크기 4096을 기록했고, mmap 후 sync-start(flags 3), cpu-access 4096바이트, sync-end(flags 7), munmap, close-dmabuf, close-backing, close-provider를 모두 결과 0으로 남겼습니다. 기록에 SYNC_START와 SYNC_END라는 이름은 없고, 이벤트 이름은 sync-start와 sync-end입니다.

실행 확인 항목: 이 구성은 simulation이 true로 표시된 가상의 시험 구성이며 실제 제품이 아닙니다. 관측은 GDB 아래에서 이루어졌고, GDB 중단점이 타이밍에 영향을 준다고 기록되어 있습니다. 물리 DMA는 not-validated, 물리 카메라·운영 응용·내부 HAL은 not-run이며, 사람 검토는 pending이고 제품 가용성은 unknown입니다. 취소 분기는 동적으로 실행되지 않았고, 관측된 cancelled_callbacks 0은 강제된 결과가 아니라고 기록되어 있습니다.

콜백과 후속 처리에서 확인한 세 프레임

가상 시험 구성입니다. 실제 제품의 지원·성능 주장으로 사용하지 마세요.

CameraSession::requestComplete는 요청 상태가 RequestCancelled이면 아무 작업 없이 반환합니다. 그 밖의 완료 요청은 EventLoop::instance()->callLater로 processRequest 호출을 이벤트 루프에 미뤄, 카메라 매니저 스레드가 막히지 않도록 합니다. processRequest는 캡처 한도에 도달했으면 바로 반환하고, 그렇지 않으면 프레임 정보를 출력한 뒤 captureCount_를 증가시킵니다. 관찰점은 processRequest 함수 안에서 captureCount_ 증가 직전입니다.

측정 자료에서 세 독립 프로세스(pid 434, 449, 464) 각각의 callback-entry와 frame-processed 이벤트는 같은 request 주소와 sequence(0, 1, 2)로 짝지어지므로, 프로세스마다 세 프레임이 한 번씩 집계됩니다. Request 상태 enum은 RequestPending, RequestComplete, RequestCancelled 순으로 선언되고 숫자 값이 명시되지 않으므로, 실제 status 1은 둘째 항목인 RequestComplete에 대응합니다. callbacks 스레드의 TID는 437, 452, 467이고, main_tid와 processed 스레드의 TID는 434, 449, 464입니다. 성공 버퍼 상태(buffer_status 0)인 buffer_sequence 0, 1, 2는 successful_buffer_sequences 0, 1, 2와 일치합니다.

실행 확인 항목: 취소 0건(cancelled_callbacks 0)은 이번 관찰값이며, 취소 분기는 동적으로 실행되지 않았으므로 관찰 0건은 강제된 결과가 아닙니다. 콜백 반환 명령은 관찰되지 않았으므로 이 측정은 취소 경로, 반환 명령, 성능에 대한 검증이 아닙니다. GDB 중단점이 타이밍에 영향을 준다는 관찰 한계가 있으며, 결과는 소스 293d751a814e0d4c34e85ad457ccd9d5eefd1a61, WSL2 커스텀 UDMABUF 커널, Virtual2 400x300 NV12 구성에만 해당하고 물리 DMA, 물리 카메라, 다른 운영 응용, 내부 HAL은 검증되지 않았습니다. 이 구성은 시뮬레이션 기반의 가상 시험 구성이며 실제 제품이 아닙니다.

재현 조건과 검증 경계

가상 시험 구성입니다. 실제 제품의 지원·성능 주장으로 사용하지 마세요.

사전 점검에서 UDMABUF와 DMA-BUF heap이 없던 기본 WSL2 커널 대신, 사용자 승인 후 Microsoft 태그 linux-msft-wsl-6.18.33.2의 정확한 UDMABUF 내장 시험 커널을 임시로 적용했습니다. GCC 13.2에서 Ubuntu GCC 15.2로의 compiler capability 차이와 binutils 2.41에서 2.46, pahole 1.25에서 1.31로의 차이는 전체 diff로 보존했고, 새 release용 모듈을 설치하지 않아 시험 중 Docker는 중지 상태로 두었습니다. UDMABUF 장치는 root 전용이어서 권한을 바꾸지 않고 root 자식 프로세스로 실행했으며, 일반 사용자 실행의 errno 13 실패도 보존했습니다. 이 구성은 시뮬레이션된 Virtual2 400x300 NV12 시험 설정이며, 실제 제품이 아니라 시뮬레이션 시험 구성입니다.

실행 확인 항목: 기본 WSL2 커널로 원복된 뒤에는 UDMABUF 할당기가 없으므로, 재현 명령을 실행하기 전에 별도로 승인된 지원 커널을 준비하고 부팅한 뒤 장치 접근을 먼저 확인해야 합니다. 과거 시험의 승인은 미래의 새 호스트 변경 승인이 아니며, 공유 커널·모듈·.wslconfig 변경이나 WSL 배포판·VM 종료는 실행 직전에 별도 승인을 받아야 합니다. 기존 PR 병합과 Pages 배포 승인은 이런 호스트 변경의 승인으로 확대되지 않으며, 이 전제는 실행 계약 근거에 따릅니다.

전용 부정 시험에서 부재 제공자는 errno 2로, 미지원 ioctl은 errno 25로 실패했으며 두 경우 모두 종료 코드 1이 기록되었습니다. 0.5초 시간 초과 시험도 timed_out 값이 true로 기록되어 실패 판정이 보존되었습니다.

같은 0.5초 시간 초과 시험에서 SYNC_END 반환값 0, munmap 반환값 0, fd 닫기 반환값 0 세 건이 기록되었고 프로세스 그룹도 남지 않았습니다. 이는 시간 초과 실패 판정과 별개로 자원 정리가 성공했음을 뜻하며, 닫기 반환값 0은 성공을 뜻할 뿐 닫기가 0건이었다는 뜻이 아닙니다. 추가 공식 cam strace는 종료 코드 0으로 정상 종료했지만, callback_observation 값이 false로 기록되어 콜백 관찰과 별도입니다. 이 구성은 실제 제품이 아닌 가상 시험 구성입니다.

임시 .wslconfig를 제거하고 커널을 원복한 결과, 실행 후 커널은 사전 시험 커널과 같은 6.18.33.2-microsoft-standard-WSL2이며 .wslconfig 파일은 존재하지 않습니다. 이 결과는 소스 293d751a814e0d4c34e85ad457ccd9d5eefd1a61 기준의 WSL2 맞춤 UDMABUF 커널, 루트 자식 프로세스, Virtual2 400x300 NV12 구성에서 얻은 것입니다. 이 구성은 시뮬레이션된 가상 테스트 구성이며 실제 제품이 아닙니다.

실행 확인 항목: 물리 DMA, 물리 카메라, 다른 제품 애플리케이션, 사내 HAL, 사람 승인(human_review: pending)은 미검증 상태입니다. GDB 중단점 관찰은 타이밍에 영향을 주며, 콜백 반환 명령은 관찰하지 않았습니다.

void CameraSession::requestComplete(Request *request)
{
    if (request->status() == Request::RequestCancelled)
        return;

    /*
     * Defer processing of the completed request to the event loop, to avoid
     * blocking the camera manager thread.
     */
    EventLoop::instance()->callLater([this, request]() { processRequest(request); });
}

void CameraSession::processRequest(Request *request)
{
    /*
     * If we've reached the capture limit, we're done. This doesn't
     * duplicate the check below that emits the captureDone signal, as this
     * function will be called for each request still in flight after the
     * capture limit is reached and we don't want to emit the signal every
     * single time.
     */
    if (captureLimit_ && captureCount_ >= captureLimit_)
        return;

    const Request::BufferMap &buffers = request->buffers();

    /*
     * Compute the frame rate. The timestamp is arbitrarily retrieved from
     * the first buffer, as all buffers should have matching timestamps.
     */
    uint64_t ts = buffers.begin()->second->metadata().timestamp;
    double fps = ts - last_;
    fps = last_ != 0 && fps ? 1000000000.0 / fps : 0.0;
    last_ = ts;

    bool requeue = true;

    std::stringstream info;
    info << ts / 1000000000 << "."
         << std::setw(6) << std::setfill('0') << ts / 1000 % 1000000
         << " (" << std::fixed << std::setprecision(2) << fps << " fps)";

    for (const auto &[stream, buffer] : buffers) {
        const FrameMetadata &metadata = buffer->metadata();

        info << " " << streamNames_[stream]
             << " seq: " << std::setw(6) << std::setfill('0') << metadata.sequence
             << " bytesused: ";

        unsigned int nplane = 0;
        for (const FrameMetadata::Plane &plane : metadata.planes()) {
            info << plane.bytesused;
            if (++nplane < metadata.planes().size())
                info << "/";
        }
    }

    if (sink_) {
        if (!sink_->processRequest(request))
            requeue = false;
    }

    std::cout << info.str() << std::endl;

    if (printMetadata_) {
        const ControlList &requestMetadata = request->metadata();
        for (const auto &[key, value] : requestMetadata) {
            const ControlId *id = controls::controls.at(key);
            std::cout << "\t" << id->name() << " = "
                  << value.toString() << std::endl;
        }
    }

    /*
     * Notify the user that capture is complete if the limit has just been
     * reached.
     */
    captureCount_++;
    if (captureLimit_ && captureCount_ >= captureLimit_) {
        captureDone.emit();
        return;
    }

    /*
     * If the frame sink holds on the request, we'll requeue it later in the
     * complete handler.
     */
    if (!requeue)
        return;

    request->reuse(Request::ReuseBuffers);
    queueRequest(request);
}
