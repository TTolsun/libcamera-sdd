Verification scope: Linking code evidence to explanations

Terms in this document: active stream, Pipeline Handler
  • Active streams: A Stream connected to the current camera configuration. If a request buffer refers to a stream of a different configuration, the submission check rejects it.
  • Pipeline Handler: A libcamera component that finds the media device of a specific hardware platform (IPU3, RKISP1, etc.), creates cameras, passes requests to the device, and returns their completion. There is one per platform.

Other terms can be found in Glossary.

Responsibilities by class

CameraManager is the entry point to libcamera, enumerating devices, associating them with pipeline managers, providing applications with access to cameras, owning camera objects, and managing their lifetimes in response to hot-plugging and hot-unplugging. Only one CameraManager instance may exist at a time, and creating an additional instance before deleting the existing instance results in undefined behavior.

Camera models a camera capable of producing one or more image streams from a single image source and is the main interface for configuring and controlling the device and capturing image streams. libcamera manages the lifetime of camera instances using std::shared_ptr, and instances must be created with create(), which returns a shared pointer. The constructors and destructor of Camera are private to prevent manual creation and destruction. Request is an object that allows an application to associate buffers and controls for each frame and queue them for processing by the camera device.

The cookie passed to the Request constructor is an opaque value for application use that is stored in the request and can be read at any time through cookie().

Camera::configure() checks access from CameraAcquired through CameraConfigured and returns the result if it is negative; after setting the stream of each configuration to nullptr, the function returns -EINVAL if validate() is not CameraConfiguration::Valid. Then, if the return value of PipelineHandler::configure is nonzero, the function returns that value; on success, the function clears the active streams and checks cfg.stream() for each configuration. If a stream is null, there is code that prints a Fatal message using LOG, then clears the active streams and returns -EINVAL, but the Fatal log terminates the program immediately after printing the message. Once all streams have been processed, the function sets the state to Configured and returns 0.

If start() succeeds while the camera is in the Configured state, the camera enters the Running state. The camera enters the Stopping state when stop() is called while it is in the Running state. The camera returns to the Configured state when stopping is complete while it is in the Stopping state. release() leaves the state unchanged in the Available state and changes it to Available in the Acquired or Configured state.

The caller may call Camera::createRequest() only when the camera is in the Configured or Running state. Camera::queueRequest may be called by the caller only when the camera is in the Running state and returns -EACCES if the request cannot be queued because the camera is not running. Camera::start() may be called only when the camera is in the Configured state.

The Camera class generally does not synchronize functions that affect camera state with each other. The caller must ensure that these functions are synchronized when necessary.

Errors and termination

Camera::queueRequest() returns 0 if it successfully queues a capture request and a negative error code if it fails; it returns -ENODEV if the camera is disconnected from the system, -EACCES if the camera is not running, and -ENOMEM if no buffer memory is available to handle the request; and if the result of isAccessAllowed(Private::CameraRunning), which checks the running state, is negative, it returns that value unchanged.

Camera::queueRequest() returns -EXDEV if the request was not created by this camera, and returns -EINVAL if the request's status is not Request::RequestPending or request->controls().infoMap() differs from &controls().

After allocating a request with createRequest(), the application must fill it with at least one capture buffer before queuing it. After checking the camera state, the owning camera, the request state, and the control information, Camera::queueRequest() checks for the presence of buffers and active streams and returns -EINVAL if there are no buffers or a buffer's stream is not active. Completion of a queued request is signaled through the requestCompleted signal.

Camera::stop() returns 0 in the actual implementation if the camera is not running; if the camera is running, it checks isAccessAllowed(Private::CameraRunning) and returns the result unchanged when it is negative. If the check passes, the function changes the state to CameraStopping, calls PipelineHandler::stop with ConnectionTypeBlocking, asserts that there are no pending requests, changes the state to CameraConfigured, and returns 0.

The API contract for Camera::stop() describes stopping capture and request processing immediately, canceling all pending requests, and completing them synchronously in an error state. The return value is 0 on success or a negative error code otherwise, with -ENODEV specified when the camera has been disconnected from the system.

Disconnection and pending requests

Camera::Private::disconnect() stores CameraConfigured only when the current state is CameraRunning, and skips this store in other states. Afterward, the function sets disconnected_ to true regardless of the state. According to the comment, the purpose of the state change is to allow the application to free resources and call release() before deleting the camera if the camera was running when the hardware was removed.

\brief Queue a request to the camera
 * \param[in] request The request to queue to the camera
 *
 * This function queues a \a request to the camera for capture.
 *
 * After allocating the request with createRequest(), the application shall
 * fill it with at least one capture buffer before queuing it. Requests that
 * contain no buffers are invalid and are rejected without being queued.
 *
 * Once the request has been queued, the camera will notify its completion
 * through the \ref requestCompleted signal.
 *
 * \context This function is \threadsafe. It may only be called when the camera
 * is in the Running state as defined in \ref camera_operation.
 *
 * \return 0 on success or a negative error code otherwise
 * \retval -ENODEV The camera has been disconnected from the system
 * \retval -EACCES The camera is not running so requests can't be queued
 * \retval -EXDEV The request does not belong to this camera
 * \retval -EINVAL The request is invalid
 * \retval -ENOMEM No buffer memory was available to handle the request
 */
int Camera::queueRequest(Request *request)
{
    Private *const d = _d();

    int ret = d->isAccessAllowed(Private::CameraRunning);
    if (ret < 0)
        return ret;

    /* Requests can only be queued to the camera that created them. */
    if (request->_d()->camera() != this) {
        LOG(Camera, Error) << "Request was not created by this camera";
        return -EXDEV;
    }

    if (request->status() != Request::RequestPending) {
        LOG(Camera, Error) << request->toString() << " is not valid";
        return -EINVAL;
    }

    /* Make sure the Request has a valid control list. */
    if (request->controls().infoMap() != &controls()) {
        LOG(Camera, Error) << "Overwriting Request::controls() is not allowed";
        return -EINVAL;
    }

    /*
     * The camera state may change until the end of the function. No locking
     * is however needed as PipelineHandler::queueRequest() will handle
     * this.
     */

    if (request->buffers().empty()) {
        LOG(Camera, Error) << "Request contains no buffers";
        return -EINVAL;
    }

    for (const auto &[stream, buffer] : request->buffers()) {
        if (d->activeStreams_.find(stream) == d->activeStreams_.end()) {
            LOG(Camera, Error) << "Invalid request";
            return -EINVAL;
        }
    }

    /* Pre-process AeEnable. */
    patchControlList(request->controls());

    d->pipe_->invokeMethod(&PipelineHandler::queueRequest,
                   ConnectionTypeQueued, request);

    return 0;
}

void Camera::Private::disconnect()
{
    /*
     * If the camera was running when the hardware was removed force the
     * state to Configured state to allow applications to free resources
     * and call release() before deleting the camera.
     */
    if (state_.load(std::memory_order_acquire) == Private::CameraRunning)
        state_.store(Private::CameraConfigured, std::memory_order_release);

    disconnected_ = true;
}
