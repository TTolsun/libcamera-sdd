Terms in this document: Pipeline Handler, IPU3
  • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.
  • IPU3 (Intel Image Processing Unit 3): the camera ISP in some Intel laptop processors. libcamera has a Pipeline Handler and an IPA for it.

Device matching and object lifetime

PipelineHandler associates media devices provided by DeviceEnumerator with pipelines that support them, and creates and manages the corresponding Camera devices. Handler instances manage their reference counts using std::shared_ptr<> and implement std::enable_shared_from_this<> to create new shared pointers in paths where only an this pointer is available in member functions. Instances must not be created directly; they must be created using PipelineHandlerFactoryBase::create().

The camera manager calls match(), the handler's entry point, on the CameraManager thread. If the implementation finds all the devices required for a pipeline, it must acquire each one using MediaDevice::acquire(), create and internally store one or more Camera instances, register them with the camera manager, and then return true. If it cannot find all the required devices, it must either acquire no devices or release all devices already acquired using MediaDevice::release(), and return false.

If there are multiple pipeline instances in the system, create a PipelineHandler for each instance and call match(). Each call must acquire the devices needed for one pipeline instance until compatible devices are exhausted. If match() returns true, create a new handler instance and call its match().

acquireMediaDevice() searches the available devices for one that matches the pattern and does not consider devices previously acquired with MediaDevice::acquire(). If the search fails or the device cannot be acquired, it returns nullptr. On success, it adds the device to an internal list and returns a shared pointer. The caller must call this function from the CameraManager thread and must not release the device directly. The device is automatically released when the handler is destroyed.

Because the Camera class handles access internally, pipeline handlers must not call acquire() or release() directly. Access can be acquired recursively within the same process, and release() must be called once for each successful acquire(). Each release() must be paired with a previously successful acquire(); calling it on a handler that has not been acquired results in undefined behavior.

acquire() locks the media devices if the usage count is 0. If locking fails, it unlocks the devices and returns false. If acquireDevice() then fails, it unlocks the devices if the usage count is 0 and returns false. On success, it increments the usage count and returns true. release() first calls releaseDevice(), and if the usage count is 1, it unlocks the media devices and then decrements the usage count.

The pipeline handler may override acquireDevice() to open devices or allocate buffers when acquiring a camera, and the default implementation returns true. The handler may override releaseDevice() to perform cleanup, such as freeing memory, when releasing a camera. If multiple cameras share resources, the handler must not release those resources until releaseDevice() has been called for all previously acquired cameras.

Configuration inputs and validation duties

The caller of PipelineHandler::generateConfiguration() must populate roles with the use cases for which to obtain a default configuration. It returns a valid CameraConfiguration if the requested roles can be fulfilled, or a null pointer otherwise. The caller can inspect the selected streams and default parameters in the returned configuration. This function may be called from any thread, must be thread-safe, and must not change the camera's state in the pipeline handler.

PipelineHandler::configure() is an interface intended to be called by the Camera class after it receives the configuration to apply from the application, and it is called from the CameraManager thread. The configuration is guaranteed to have been validated by CameraConfiguration::validate(), so the pipeline handler implementation must not perform additional validation and may use custom fields stored in its own CameraConfiguration derived class. When configuring the camera, the implementation must use StreamConfiguration::setStream() to associate a Stream instance with each StreamConfiguration entry. It returns 0 on success or a negative error code on failure.

Stopping and outstanding requests

PipelineHandler::stop moves all pending requests from waitingRequests_ to a local queue. According to the comment, this prevents pending requests from being requeued when completeRequest() is called inside stopDevice(), and allows the requests to be cancelled after stopping the device to preserve their order. It then immediately calls stopDevice(camera).

After stopDevice() returns, PipelineHandler::stop() takes the detached pending requests one by one from the front. For each request, it calls cancel() to mark it as cancelled, then calls doQueueRequest(). Implementers of PipelineHandler::stopDevice() must immediately stop capture and request processing for all running streams. All pending requests must be cancelled and completed immediately with an error status.

At the end, PipelineHandler::stop() uses ASSERT to check whether queuedRequests_ and waitingRequests_ are each empty. It then initializes requestSequence_ to 0. At the end, completeRequest() calls doQueueRequests(camera) so that pending requests can be passed to the pipeline.

Input Size Search Boundaries in IPU3

ImgUDevice::calculatePipeConfig() calculates minIfWidth as the greater of the input width minus ImgUDevice::kIFMaxCropWidth and ImgUDevice::kIFMaxCropWidth. minIfHeight is calculated as the greater of the input height minus ImgUDevice::kIFMaxCropHeight and ImgUDevice::kIFMaxCropHeight.

ImgUDevice::calculatePipeConfig aligns the width and height to alignUp, then calls calculateBDS in an outer loop while the width is at least minIfWidth and an inner loop while the height is at least minIfHeight. Before the second search, it reinitializes both values to alignUp and searches with height in the outer loop and width in the inner loop, while each remains at or above the same respective minimum. In each iteration, the width decreases by kIFAlignWidth and the height decreases by kIFAlignHeight, and the corresponding value is not reinitialized when the inner loop ends. According to the comment, calculateBDSHeight crops up to kIFMaxCropHeight lines from the input formatter height, so if the height falls below that, the minimum input formatter height wraps around.

\brief Search and acquire a MediaDevice matching a device pattern
 * \param[in] enumerator Enumerator containing all media devices in the system
 * \param[in] dm Device match pattern
 *
 * Search the device \a enumerator for an available media device matching the
 * device match pattern \a dm. Matching media device that have previously been
 * acquired by MediaDevice::acquire() are not considered. If a match is found,
 * the media device is acquired and returned. The caller shall not release the
 * device explicitly, it will be automatically released when the pipeline
 * handler is destroyed.
 *
 * \context This function shall be called from the CameraManager thread.
 *
 * \return A shared pointer to the matching MediaDevice, or nullptr if no match
 * is found
 */
std::shared_ptr<MediaDevice>
PipelineHandler::acquireMediaDevice(DeviceEnumerator *enumerator,
                    const DeviceMatch &dm)
{
    std::shared_ptr<MediaDevice> media = enumerator->search(dm);
    if (!media)
        return nullptr;

    if (!media->acquire())
        return nullptr;

    mediaDevices_.push_back(media);

    return media;
}

/**
 * \brief Acquire exclusive access to the pipeline handler for the process
 *
 * This function locks all the media devices used by the pipeline to ensure
 * that no other process can access them concurrently.
 *
 * Access to a pipeline handler may be acquired recursively from within the
 * same process. Every successful acquire() call shall be matched with a
 * release() call. This allows concurrent access to the same pipeline handler
 * from different cameras within the same process.
 *
 * Pipeline handlers shall not call this function directly as the Camera class
 * handles access internally.
 *
 * \context This function is called from the CameraManager thread.
 *
 * \return True if the pipeline handler was acquired, false if another process
 * has already acquired it
 * \sa release()
 */
bool PipelineHandler::acquire(Camera *camera)
{
    if (useCount_ == 0) {
        for (std::shared_ptr<MediaDevice> &media : mediaDevices_) {
            if (!media->lock()) {
                unlockMediaDevices();
                return false;
            }
        }
    }

    if (!acquireDevice(camera)) {
        if (useCount_ == 0)
            unlockMediaDevices();

        return false;
    }

    ++useCount_;
    return true;
}

/**
 * \brief Release exclusive access to the pipeline handler
 * \param[in] camera The camera for which to release data
 *
 * This function releases access to the pipeline handler previously acquired by
 * a call to acquire(). Every release() call shall match a previous successful
 * acquire() call. Calling this function on a pipeline handler that hasn't been
 * acquired results in undefined behaviour.
 *
 * Pipeline handlers shall not call this function directly as the Camera class
 * handles access internally.
 *
 * \context This function is called from the CameraManager thread.
 *
 * \sa acquire()
 */
void PipelineHandler::release(Camera *camera)
{
    ASSERT(useCount_);

    releaseDevice(camera);

    if (useCount_ == 1)
        unlockMediaDevices();

    --useCount_;
}

\brief Stop capturing from all running streams and cancel pending requests
 * \param[in] camera The camera to stop
 *
 * This function stops capturing and processing requests immediately. All
 * pending requests are cancelled and complete immediately in an error state.
 *
 * \context This function is called from the CameraManager thread.
 */
void PipelineHandler::stop(Camera *camera)
{
    /*
     * Take all waiting requests so that they are not requeued in response
     * to completeRequest() being called inside stopDevice(). Cancel them
     * after the device to keep them in order.
     */
    Camera::Private *data = camera->_d();
    std::queue<Request *> waitingRequests;
    waitingRequests.swap(data->waitingRequests_);

    /* Stop the pipeline handler and let the queued requests complete. */
    stopDevice(camera);

    /* Cancel and signal as complete all waiting requests. */
    while (!waitingRequests.empty()) {
        Request *request = waitingRequests.front();
        waitingRequests.pop();

        /*
         * Cancel all requests by marking them as cancelled and calling
         * doQueueRequest() instead of cancelRequest(). This ensures
         * that the requests get a sequence number and are temporarily
         * added to queuedRequests_ so they can be properly completed in
         * completeRequest().
         */
        request->_d()->cancel();
        doQueueRequest(request);
    }

    /* Make sure no requests are pending. */
    ASSERT(data->queuedRequests_.empty());
    ASSERT(data->waitingRequests_.empty());

    data->requestSequence_ = 0;
}

\brief Complete a buffer for a request
 * \param[in] request The request the buffer belongs to
 * \param[in] buffer The buffer that has completed
 *
 * This function shall be called by pipeline handlers to signal completion of
 * the \a buffer part of the \a request. It notifies applications of buffer
 * completion and updates the request's internal buffer tracking. The request
 * is not completed automatically when the last buffer completes to give
 * pipeline handlers a chance to perform any operation that may still be
 * needed. They shall complete requests explicitly with completeRequest().
 *
 * \context This function shall be called from the CameraManager thread.
 *

 * otherwise
 */
bool PipelineHandler::completeBuffer(Request *request, FrameBuffer *buffer)

    Camera *camera = request->_d()->camera();
    camera->bufferCompleted.emit(request, buffer);

}

/**
 * \brief Signal request completion
 * \param[in] request The request that has completed
 *
 * The pipeline handler shall call this function to notify the \a camera that
 * the request has completed. The request is no longer managed by the pipeline
 * handler and shall not be accessed once this function returns.
 *
 * This function ensures that requests will be returned to the application in
 * submission order, the pipeline handler may call it on any complete request
 * without any ordering constraint.
 *
 * \context This function shall be called from the CameraManager thread.
 */
void PipelineHandler::completeRequest(Request *request)
{
    Camera *camera = request->_d()->camera();

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);
    }

    /* Allow any waiting requests to be queued to the pipeline. */
    doQueueRequests(camera);
}

/**
 * \brief Cancel request and signal its completion
 * \param[in] request The request to cancel
 *
 * This function cancels and completes the request. The same rules as for
 * completeRequest() apply.
 */
void PipelineHandler::cancelRequest(Request *request)
{
    request->_d()->cancel();
    completeRequest(request);
}
