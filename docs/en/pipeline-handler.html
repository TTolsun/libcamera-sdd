Terms in this document: Pipeline Handler, IPU3
  • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.
  • IPU3 (Intel Image Processing Unit 3): the camera ISP in some Intel laptop processors. libcamera has a Pipeline Handler and an IPA for it.

Device matching and object lifetime

PipelineHandler matches the media device provided by DeviceEnumerator with a pipeline that supports it, and creates and manages the corresponding Camera device. Handler instances use std::shared_ptr<> for reference counting and implement std::enable_shared_from_this<> to create a new std::shared_ptr<> in code paths where only a this pointer is available in a member function. Instances must not be created directly and must always be created through PipelineHandlerFactoryBase::create().

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL50 excerpt · Full source L50

If PipelineHandler::match(), called by the camera manager, finds all media devices needed for a single pipeline, it must acquire each one with MediaDevice::acquire(), create one or more Camera instances, store them internally, register them with the camera manager, and then return true. If it does not find all the required devices, it must either refrain from acquiring any devices or release all devices already acquired with MediaDevice::release(), and return false. If there are multiple pipeline instances, each call must acquire the devices required for one instance; if it returns true, a new handler instance is created and match() is called again.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL50 excerpt · Full source L50

PipelineHandler::acquireMediaDevice() searches for an available media device matching the pattern, excluding devices that have already been acquired. If the search or device acquisition fails, it returns nullptr. If successful, it adds the device to an internal list and returns a shared pointer. The caller must not release the returned device directly; the device is released when the handler is destroyed. This function must be called from the CameraManager thread.

Paragraph evidence · 2
  • src/libcamera/pipeline_handler.cppL119 excerpt · Full source L119 · L50 excerpt · Full source L50

PipelineHandler::acquire() locks the media devices used by the pipeline to prevent concurrent access by other processes, and they can be acquired recursively within the same process. Each successful acquire() call must be paired with one release() call, and each release() must be paired with a previously successful acquire(). Handlers must not call the two functions directly; the Camera class handles access. Calling release() on a handler that has not acquired the devices results in undefined behavior.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL119 excerpt · Full source L119

PipelineHandler::acquire() locks the media device when useCount_ is 0; if locking fails, it unlocks the device and returns false. If acquireDevice(camera) then fails, it unlocks the device if useCount_ is 0 and returns false; if it succeeds, it increments useCount_ and returns true. PipelineHandler::release() first calls releaseDevice(camera), and if useCount_ is 1, it unlocks the media device and then decrements useCount_.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL119 excerpt · Full source L119

The pipeline handler may override acquireDevice() to handle resources when a camera is acquired, such as opening devices or allocating buffers, and may override releaseDevice() to perform cleanup when a camera is released, such as freeing memory. releaseDevice() is called once for each camera being released, and the handler must not release resources shared by multiple cameras until releaseDevice() has been called for all previously acquired cameras.

Configuration inputs and validation duties

The caller must fill roles with the use cases for which a default configuration is desired. PipelineHandler::generateConfiguration() returns a valid CameraConfiguration if it can satisfy the requested roles, and a null pointer otherwise. The caller can inspect the returned configuration to check the selected streams and default parameters. This function may be called from any thread, must be thread-safe, and must not change the state of camera in the pipeline handler.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL271 excerpt · Full source L271

PipelineHandler::configure() is an interface intended to be called by the Camera class, which receives the configuration to be applied from the application, and is called from the CameraManager thread. The configuration is guaranteed to have been validated by CameraConfiguration::validate(), so pipeline handler implementations must not perform additional validation and may use custom fields stored in their own CameraConfiguration derived class. Implementations must associate a Stream instance with each StreamConfiguration entry using StreamConfiguration::setStream(). This function returns 0 on success or a negative error code on failure.

Stopping and outstanding requests

PipelineHandler::stop separates the pending requests in waitingRequests_ by swapping them with the local queue waitingRequests. According to the comment, this prevents pending requests from being requeued when completeRequest() is called inside stopDevice(). Immediately after separating them, it calls stopDevice(camera). After stopDevice() returns, PipelineHandler::stop() takes the separated pending requests from the front one at a time, cancels them, and calls doQueueRequest() for each request.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL359 excerpt · Full source L359

The stopDevice() implementer must immediately stop capture and request processing for all running streams. The implementer must also cancel all pending requests and immediately complete them with an error status. Finally, PipelineHandler::stop() uses ASSERT to check that queuedRequests_ and waitingRequests_ are empty. It then initializes requestSequence_ to 0.

Input Size Search Boundaries in IPU3

ImgUDevice::calculatePipeConfig() calculates minIfWidth as std::max(in.width - ImgUDevice::kIFMaxCropWidth, ImgUDevice::kIFMaxCropWidth) and minIfHeight as std::max(in.height - ImgUDevice::kIFMaxCropHeight, ImgUDevice::kIFMaxCropHeight). It searches while the width and height are ifWidth >= minIfWidth and ifHeight >= minIfHeight, respectively; in the first search, width is the outer loop, and in the subsequent search, height is the outer loop.

Paragraph evidence · 1
  • src/libcamera/pipeline/ipu3/imgu.cppL407 excerpt · Full source L407

ImgUDevice::calculatePipeConfig() returns an empty configuration if in.height is less than ImgUDevice::kIFMaxCropHeight. According to the comment, calculateBDSHeight() crops up to kIFMaxCropHeight lines from the height, so the minimum height wraps if the height falls below that. calculatePipeConfig() sets minIfHeight to max(in.height - ImgUDevice::kIFMaxCropHeight, ImgUDevice::kIFMaxCropHeight) and passes the height to calculateBDS() while the aligned ifHeight is greater than or equal to this value.

\brief Search and acquire a MediaDevice matching a device pattern
 * \param[in] enumerator Enumerator containing all media devices in the system
 * \param[in] dm Device match pattern
 *
 * Search the device \a enumerator for an available media device matching the
 * device match pattern \a dm. Matching media device that have previously been
 * acquired by MediaDevice::acquire() are not considered. If a match is found,
 * the media device is acquired and returned. The caller shall not release the
 * device explicitly, it will be automatically released when the pipeline
 * handler is destroyed.
 *
 * \context This function shall be called from the CameraManager thread.
 *
 * \return A shared pointer to the matching MediaDevice, or nullptr if no match
 * is found
 */
std::shared_ptr<MediaDevice>
PipelineHandler::acquireMediaDevice(DeviceEnumerator *enumerator,
                    const DeviceMatch &dm)
{
    std::shared_ptr<MediaDevice> media = enumerator->search(dm);
    if (!media)
        return nullptr;

    if (!media->acquire())
        return nullptr;

    mediaDevices_.push_back(media);

    return media;
}

/**
 * \brief Acquire exclusive access to the pipeline handler for the process
 *
 * This function locks all the media devices used by the pipeline to ensure
 * that no other process can access them concurrently.
 *
 * Access to a pipeline handler may be acquired recursively from within the
 * same process. Every successful acquire() call shall be matched with a
 * release() call. This allows concurrent access to the same pipeline handler
 * from different cameras within the same process.
 *
 * Pipeline handlers shall not call this function directly as the Camera class
 * handles access internally.
 *
 * \context This function is called from the CameraManager thread.
 *
 * \return True if the pipeline handler was acquired, false if another process
 * has already acquired it
 * \sa release()
 */
bool PipelineHandler::acquire(Camera *camera)
{
    if (useCount_ == 0) {
        for (std::shared_ptr<MediaDevice> &media : mediaDevices_) {
            if (!media->lock()) {
                unlockMediaDevices();
                return false;
            }
        }
    }

    if (!acquireDevice(camera)) {
        if (useCount_ == 0)
            unlockMediaDevices();

        return false;
    }

    ++useCount_;
    return true;
}

/**
 * \brief Release exclusive access to the pipeline handler
 * \param[in] camera The camera for which to release data
 *
 * This function releases access to the pipeline handler previously acquired by
 * a call to acquire(). Every release() call shall match a previous successful
 * acquire() call. Calling this function on a pipeline handler that hasn't been
 * acquired results in undefined behaviour.
 *
 * Pipeline handlers shall not call this function directly as the Camera class
 * handles access internally.
 *
 * \context This function is called from the CameraManager thread.
 *
 * \sa acquire()
 */
void PipelineHandler::release(Camera *camera)
{
    ASSERT(useCount_);

    releaseDevice(camera);

    if (useCount_ == 1)
        unlockMediaDevices();

    --useCount_;
}

\brief Stop capturing from all running streams and cancel pending requests
 * \param[in] camera The camera to stop
 *
 * This function stops capturing and processing requests immediately. All
 * pending requests are cancelled and complete immediately in an error state.
 *
 * \context This function is called from the CameraManager thread.
 */
void PipelineHandler::stop(Camera *camera)
{
    /*
     * Take all waiting requests so that they are not requeued in response
     * to completeRequest() being called inside stopDevice(). Cancel them
     * after the device to keep them in order.
     */
    Camera::Private *data = camera->_d();
    std::queue<Request *> waitingRequests;
    waitingRequests.swap(data->waitingRequests_);

    /* Stop the pipeline handler and let the queued requests complete. */
    stopDevice(camera);

    /* Cancel and signal as complete all waiting requests. */
    while (!waitingRequests.empty()) {
        Request *request = waitingRequests.front();
        waitingRequests.pop();

        /*
         * Cancel all requests by marking them as cancelled and calling
         * doQueueRequest() instead of cancelRequest(). This ensures
         * that the requests get a sequence number and are temporarily
         * added to queuedRequests_ so they can be properly completed in
         * completeRequest().
         */
        request->_d()->cancel();
        doQueueRequest(request);
    }

    /* Make sure no requests are pending. */
    ASSERT(data->queuedRequests_.empty());
    ASSERT(data->waitingRequests_.empty());

    data->requestSequence_ = 0;
}

\brief Complete a buffer for a request
 * \param[in] request The request the buffer belongs to
 * \param[in] buffer The buffer that has completed
 *
 * This function shall be called by pipeline handlers to signal completion of
 * the \a buffer part of the \a request. It notifies applications of buffer
 * completion and updates the request's internal buffer tracking. The request
 * is not completed automatically when the last buffer completes to give
 * pipeline handlers a chance to perform any operation that may still be
 * needed. They shall complete requests explicitly with completeRequest().
 *
 * \context This function shall be called from the CameraManager thread.
 *
 * \return True if all buffers contained in the request have completed, false
 * otherwise
 */
bool PipelineHandler::completeBuffer(Request *request, FrameBuffer *buffer)
{
    Camera *camera = request->_d()->camera();
    camera->bufferCompleted.emit(request, buffer);
    return request->_d()->completeBuffer(buffer);
}

/**
 * \brief Signal request completion
 * \param[in] request The request that has completed
 *
 * The pipeline handler shall call this function to notify the \a camera that
 * the request has completed. The request is no longer managed by the pipeline
 * handler and shall not be accessed once this function returns.
 *
 * This function ensures that requests will be returned to the application in
 * submission order, the pipeline handler may call it on any complete request
 * without any ordering constraint.
 *
 * \context This function shall be called from the CameraManager thread.
 */
void PipelineHandler::completeRequest(Request *request)
{
    Camera *camera = request->_d()->camera();

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);
    }

    /* Allow any waiting requests to be queued to the pipeline. */
    doQueueRequests(camera);
}

/**
 * \brief Cancel request and signal its completion
 * \param[in] request The request to cancel
 *
 * This function cancels and completes the request. The same rules as for
 * completeRequest() apply.
 */
void PipelineHandler::cancelRequest(Request *request)
{
    request->_d()->cancel();
    completeRequest(request);
}
