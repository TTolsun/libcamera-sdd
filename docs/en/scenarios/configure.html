Stream configuration to prepare before capture

Camera::configure() is the function that selects, before capture starts, the group of streams to participate in the capture and the configuration of each stream. The caller specifies the streams and configuration to participate by populating config. This configuration is created by generateConfiguration() and adjusted by the caller with CameraConfiguration::validate(). This function accepts only fully valid configurations.

Before calling configure(), the caller must call acquire() to secure exclusive access to the camera. This function may only be called when the camera is in the Acquired or Configured state, and the caller must synchronize this call with other functions that change the camera state. If exclusive access is not secured, the -EACCES error is returned, and -EACCES is also returned when the camera is not in a state where it can be configured. If the camera has been disconnected from the system, configure() returns -ENODEV.

Where to check configuration application and success status

Camera::configure() first returns the return value of d->isAccessAllowed(Private::CameraAcquired, Private::CameraConfigured) as is when that value is less than 0. Next, cfg.setStream(nullptr) is called for every item in the for loop to clear the previous Stream connections. Then, if the result of config->validate() is not CameraConfiguration::Valid, "Can't configure camera with invalid configuration" is logged via LOG(Camera, Error), and -EINVAL is returned. Therefore, even if validation fails, clearing Stream connections has already been completed.

If validation passes, Camera::configure() calls the pipeline handler's configure through d->pipe_->invokeMethod(&PipelineHandler::configure, ConnectionTypeBlocking, this, config). If the call result ret is nonzero, return ret; returns that value unchanged, and in this case the subsequent Stream connection update code is not executed.

After invokeMethod returns 0, if the loop has an entry whose cfg.stream() is nullptr, execution enters the path that prints "Pipeline handler failed to update stream configuration" with LOG(Camera, Fatal). The API documentation explains that on return, the StreamConfiguration entries in config are linked to the Stream retrieved with StreamConfiguration::stream(), while the code checks entries missing this link through the Fatal path. Because the documentation states that Fatal aborts execution after printing the message, d->activeStreams_.clear() and return -EINVAL; are not executed, and in check order, preceding entries have already finished storing to configuration_ and inserting into activeStreams_.

If invokeMethod returns 0 and cfg.stream() is not nullptr for all entries, the code clears the list using d->activeStreams_.clear() before the loop, then for each entry stores stream->configuration_ = cfg; and calls d->activeStreams_.insert(stream);. After the loop, the code changes the state to CameraConfigured using d->setState(Private::CameraConfigured); and returns success using return 0;.

\brief Configure the camera prior to capture
 * \param[in] config The camera configurations to setup
 *
 * Prior to starting capture, the camera must be configured to select a
 * group of streams to be involved in the capture and their configuration.
 * The caller specifies which streams are to be involved and their configuration
 * by populating \a config.
 *
 * The configuration is created by generateConfiguration(), and adjusted by the
 * caller with CameraConfiguration::validate(). This function only accepts fully
 * valid configurations and returns an error if \a config is not valid.
 *
 * Exclusive access to the camera shall be ensured by a call to acquire() prior
 * to calling this function, otherwise an -EACCES error will be returned.
 *
 * \context This function may only be called when the camera is in the Acquired
 * or Configured state as defined in \ref camera_operation, and shall be
 * synchronized by the caller with other functions that affect the camera
 * state.
 *
 * Upon return the StreamConfiguration entries in \a config are associated with
 * Stream instances which can be retrieved with StreamConfiguration::stream().
 *
 * \return 0 on success or a negative error code otherwise
 * \retval -ENODEV The camera has been disconnected from the system
 * \retval -EACCES The camera is not in a state where it can be configured
 * \retval -EINVAL The configuration is not valid
 */

int Camera::configure(CameraConfiguration *config)
{
    Private *const d = _d();

    int ret = d->isAccessAllowed(Private::CameraAcquired,
                     Private::CameraConfigured);
    if (ret < 0)
        return ret;

    for (auto &cfg : *config)
        cfg.setStream(nullptr);

    if (config->validate() != CameraConfiguration::Valid) {
        LOG(Camera, Error)
            << "Can't configure camera with invalid configuration";
        return -EINVAL;
    }

    std::ostringstream msg("configuring streams:", std::ios_base::ate);

    for (unsigned int index = 0; index < config->size(); ++index) {
        StreamConfiguration &cfg = config->at(index);
        msg << " (" << index << ") " << cfg.toString();
    }

    LOG(Camera, Info) << msg.str();

    ret = d->pipe_->invokeMethod(&PipelineHandler::configure,
                     ConnectionTypeBlocking, this, config);
    if (ret)
        return ret;

    d->activeStreams_.clear();
    for (const StreamConfiguration &cfg : *config) {
        Stream *stream = cfg.stream();
        if (!stream) {
            LOG(Camera, Fatal)
                << "Pipeline handler failed to update stream configuration";
            d->activeStreams_.clear();
            return -EINVAL;
        }

        stream->configuration_ = cfg;
        d->activeStreams_.insert(stream);
    }

    d->setState(Private::CameraConfigured);

    return 0;
}
