Responsibility for notifying request completion and ending access

Responsibility for notifying request completion and ending access

completeRequest is the function a pipeline handler uses to notify camera that a request has completed. The handler must call this function from the CameraManager thread. After this function returns, the handler no longer manages the request, and must not access that request.

Even if the last buffer of a request is completed with completeBuffer, the request is not completed automatically. The request must be explicitly completed with completeRequest(). The handler may pass completed requests to completeRequest in any order, without ordering constraints, and the order in which requests are returned to the application is still guaranteed to be submission order.

The path that checks waiting requests and notifies the application

Request::Private::complete() first checks, using ASSERT(request->status() == RequestPending) and ASSERT(!hasPendingBuffers()), that the request is in the RequestPending state and that no pending buffers remain. Then request->status_ is set to RequestCancelled when cancelled_ is true, and to RequestComplete otherwise. Because ASSERT generates no code when NDEBUG is defined before log.h is included, this check is not performed in such builds.

PipelineHandler::completeRequest() repeats until queuedRequests_ is empty, checking the front request through front(). If the front request's status() is RequestPending, the loop exits through break without calling pop_front() or camera->requestComplete(). If that status is not RequestPending, after ASSERT(!req->hasPendingBuffers()) is checked, the request is removed from the queue through data->queuedRequests_.pop_front(), and camera->requestComplete(req) is called. Here, break exits only the loop without canceling the request.

Camera::requestComplete() calls _d()->isAccessAllowed(Private::CameraStopping, Private::CameraRunning, true) to check whether the current state is between CameraStopping and CameraRunning. Because the allowDisconnected argument is true, even a disconnected camera is not blocked by the -ENODEV check; 0 is returned if the state is within the range, and -EACCES is returned if the state is outside the range. If the return value is non-zero, LOG(Camera, Fatal) prints Trying to complete a request when stopped, and the Fatal log aborts execution. If the return value is 0, the completed request is reported to the application through requestCompleted.emit(request).

After the loop ends, PipelineHandler::completeRequest() unconditionally calls doQueueRequests(camera). This call also runs when the loop is exited through break; according to the comment, it serves to allow waiting requests to be queued to the pipeline.

\brief Complete a buffer for a request
 * \param[in] request The request the buffer belongs to
 * \param[in] buffer The buffer that has completed
 *
 * This function shall be called by pipeline handlers to signal completion of
 * the \a buffer part of the \a request. It notifies applications of buffer
 * completion and updates the request's internal buffer tracking. The request
 * is not completed automatically when the last buffer completes to give
 * pipeline handlers a chance to perform any operation that may still be
 * needed. They shall complete requests explicitly with completeRequest().
 *
 * \context This function shall be called from the CameraManager thread.
 *
 * \return True if all buffers contained in the request have completed, false
 * otherwise
 */
bool PipelineHandler::completeBuffer(Request *request, FrameBuffer *buffer)
{
    Camera *camera = request->_d()->camera();
    camera->bufferCompleted.emit(request, buffer);
    return request->_d()->completeBuffer(buffer);
}

void PipelineHandler::completeRequest(Request *request)
{
    Camera *camera = request->_d()->camera();

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);
    }

    /* Allow any waiting requests to be queued to the pipeline. */
    doQueueRequests(camera);
}

\brief Handle request completion and notify application
 * \param[in] request The request that has completed
 *
 * This function is called by the pipeline handler to notify the camera that
 * the request has completed. It emits the requestCompleted signal.
 */
void Camera::requestComplete(Request *request)
{
    /* Disconnected cameras are still able to complete requests. */
    if (_d()->isAccessAllowed(Private::CameraStopping, Private::CameraRunning,
                  true))
        LOG(Camera, Fatal) << "Trying to complete a request when stopped";

    requestCompleted.emit(request);
}

int Camera::Private::isAccessAllowed(State low, State high,
                     bool allowDisconnected,
                     const char *from) const
{
    if (!allowDisconnected && disconnected_)
        return -ENODEV;

    State currentState = state_.load(std::memory_order_acquire);
    if (currentState >= low && currentState <= high)
        return 0;

    ASSERT(static_cast<unsigned int>(low) < std::size(camera_state_names) &&
           static_cast<unsigned int>(high) < std::size(camera_state_names));

    LOG(Camera, Error) << "Camera in " << camera_state_names[currentState]
               << " state trying " << from
               << "() requiring state between "
               << camera_state_names[low] << " and "
               << camera_state_names[high];

    return -EACCES;
}

void Request::Private::complete()
{
    Request *request = _o<Request>();

    ASSERT(request->status() == RequestPending);
    ASSERT(!hasPendingBuffers());

    request->status_ = cancelled_ ? RequestCancelled : RequestComplete;

    LOG(Request, Debug) << request->toString();

    LIBCAMERA_TRACEPOINT(request_complete, this);
}
