Responsibility for notifying request completion and access termination

Responsibility for notifying request completion and access termination

completeRequest is the function a pipeline handler uses to notify camera that a completed request is ready. The handler shall call this function from the CameraManager thread. After the function returns, the handler no longer manages that request, and must not access that request.

Even when the last buffer is completed with completeBuffer, the request is not automatically completed. The request must be explicitly completed with completeRequest(). The handler may pass completed requests to completeRequest in any order without ordering constraints, and even then, the order of requests returned to the application is guaranteed to be submission order.

Path for checking waiting requests in the queue and notifying the app

Request::Private::complete() first checks, with ASSERT(request->status() == RequestPending) and ASSERT(!hasPendingBuffers()), that the request is in the RequestPending state and has no pending buffers. Then it sets request->status_ to RequestCancelled if cancelled_ is true, and to RequestComplete if it is false. This ASSERT generates no code if NDEBUG is defined before log.h is included, so in such builds this check is not performed.

PipelineHandler::completeRequest() repeats until queuedRequests_ is empty and checks the front request with front(). If the status() of the front request is RequestPending, it exits the loop with break and does not call pop_front(), and it does not call camera->requestComplete() either. If that status is not RequestPending, it checks ASSERT(!req->hasPendingBuffers()) and then removes the request from the queue with data->queuedRequests_.pop_front() and calls camera->requestComplete(req). Here, break exits only the loop without canceling the request.

Camera::requestComplete() calls _d()->isAccessAllowed(Private::CameraStopping, Private::CameraRunning, true) to check whether the current state is between CameraStopping and CameraRunning. Because the allowDisconnected argument is true, a disconnected camera is also not blocked by the -ENODEV check, and the function returns 0 if the state is within the range or -EACCES if it is outside. If the return value is not 0, LOG(Camera, Fatal) outputs Trying to complete a request when stopped, and the Fatal log aborts execution. If the return value is 0, the function notifies the application of the completed request via requestCompleted.emit(request).

After the loop ends, PipelineHandler::completeRequest() unconditionally calls doQueueRequests(camera). This call also runs when the loop is exited via break, and according to the comment, it serves to allow waiting requests to be queued to the pipeline.

\brief Complete a buffer for a request
 * \param[in] request The request the buffer belongs to
 * \param[in] buffer The buffer that has completed
 *
 * This function shall be called by pipeline handlers to signal completion of
 * the \a buffer part of the \a request. It notifies applications of buffer
 * completion and updates the request's internal buffer tracking. The request
 * is not completed automatically when the last buffer completes to give
 * pipeline handlers a chance to perform any operation that may still be
 * needed. They shall complete requests explicitly with completeRequest().
 *
 * \context This function shall be called from the CameraManager thread.
 *
 * \return True if all buffers contained in the request have completed, false
 * otherwise
 */
bool PipelineHandler::completeBuffer(Request *request, FrameBuffer *buffer)
{
    Camera *camera = request->_d()->camera();
    camera->bufferCompleted.emit(request, buffer);
    return request->_d()->completeBuffer(buffer);
}

void PipelineHandler::completeRequest(Request *request)
{
    Camera *camera = request->_d()->camera();

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);
    }

    /* Allow any waiting requests to be queued to the pipeline. */
    doQueueRequests(camera);
}

\brief Handle request completion and notify application
 * \param[in] request The request that has completed
 *
 * This function is called by the pipeline handler to notify the camera that
 * the request has completed. It emits the requestCompleted signal.
 */
void Camera::requestComplete(Request *request)
{
    /* Disconnected cameras are still able to complete requests. */
    if (_d()->isAccessAllowed(Private::CameraStopping, Private::CameraRunning,
                  true))
        LOG(Camera, Fatal) << "Trying to complete a request when stopped";

    requestCompleted.emit(request);
}

int Camera::Private::isAccessAllowed(State low, State high,
                     bool allowDisconnected,
                     const char *from) const
{
    if (!allowDisconnected && disconnected_)
        return -ENODEV;

    State currentState = state_.load(std::memory_order_acquire);
    if (currentState >= low && currentState <= high)
        return 0;

    ASSERT(static_cast<unsigned int>(low) < std::size(camera_state_names) &&
           static_cast<unsigned int>(high) < std::size(camera_state_names));

    LOG(Camera, Error) << "Camera in " << camera_state_names[currentState]
               << " state trying " << from
               << "() requiring state between "
               << camera_state_names[low] << " and "
               << camera_state_names[high];

    return -EACCES;
}

void Request::Private::complete()
{
    Request *request = _o<Request>();

    ASSERT(request->status() == RequestPending);
    ASSERT(!hasPendingBuffers());

    request->status_ = cancelled_ ? RequestCancelled : RequestComplete;

    LOG(Request, Debug) << request->toString();

    LIBCAMERA_TRACEPOINT(request_complete, this);
}
