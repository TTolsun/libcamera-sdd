Terms in this document: IPA, IPC, tuning file, software ISP, and 6 others
  • IPA (Image Processing Algorithms): a separate module (.so) holding the image-quality algorithms. It reads the statistics sent by the ISP and computes the ISP settings for the next frame. It is kept apart from libcamera itself so that vendors can ship it without publishing the source.
  • IPC (Inter-Process Communication): message exchange between separate processes. Unsigned IPA modules run in a separate process, so libcamera calls them over IPC.
  • Tuning file: a YAML file with per-sensor and per-platform algorithm parameters (correction tables, colour matrices and so on). The IPA reads it at start-up.
  • Software ISP: the libcamera component that does ISP processing on the CPU or GPU for devices without a hardware ISP. The source calls it software_isp and softisp.
  • ISP (Image Signal Processor): the processing unit that turns the sensor's raw (bayer) data into a usable image. It performs black-level correction, lens shading correction, white balance, debayering and more.
  • Shader: a small program that runs on the GPU. The software ISP can perform debayering and colour correction in GPU shaders.
  • LSC (Lens Shading Correction): correction for lens shading, where the image edges are darker or tinted compared with the centre because of the lens. It multiplies the image by a correction table laid out as a grid.
  • Proxy: a stand-in object that takes calls through the same interface instead of calling the IPA module directly, and forwards them to the IPA thread or a separate process. It is generated from the mojom definition at build time.
  • RKISP1 (Rockchip Image Signal Processor 1): the camera ISP in Rockchip SoCs, the NXP i.MX8MP and others. libcamera has a Pipeline Handler and an IPA for it.
  • IPU3 (Intel Image Processing Unit 3): the camera ISP in some Intel laptop processors. libcamera has a Pipeline Handler and an IPA for it.

Other terms are in the Glossary.

Module discovery and isolation conditions

IPAManager::IPAManager first searches the user-specified ipa.module_paths paths, skips empty paths, and passes each remaining path to addDir(). Next, if utils::libcameraBuildPath() is not an empty string, it appends src/ipa to that path and searches to a maximum depth of 2. Finally, it searches IPA_MODULE_DIR, the installed system path.

IPAModule::match returns true if info_.pipelineVersion is greater than or equal to minVersion and less than or equal to maxVersion, and info_.name equals name. If any of these conditions is not met, it returns false.

createIPA first searches for module by name and version range, and returns nullptr if there is no module. If a module exists, it creates a T::Threaded proxy when isSignatureValid(m) is true and a T::Isolated proxy when it is false. If isValid() of the created proxy is false, it logs an error and returns nullptr; if true, it returns the proxy.

IPAManager::isSignatureValid returns false if HAVE_IPA_PUBKEY is not enabled. If it is enabled and forceIsolation_ is true, it returns false; otherwise, it opens the IPA file read-only and returns false if opening fails. It returns false even if the file mapping result is empty. Otherwise, it logs the result of pubKey_.verify(data, ipa->signature()) and returns that result.

Thread and process boundaries

The Threaded init template directly calls ipa_->init() using the parameters it received. If the return type is not void, it stores the return value in _ret and returns it; if the return type is void, it returns without a value. In the init branch, it calls the IPA method and then passes the address of thread_ to proxy_.moveToThread.

The Threaded start template branch sets state_ to ProxyRunning and then calls thread_.start() to start the worker thread. It then uses proxy_.invokeMethod() to call ThreadProxy::start with the ConnectionTypeBlocking connection type and parameters generated by the template, and returns the result. In the normal synchronous method branch, excluding init, start, and stop, the generated Threaded proxy method directly calls the method of the same name on ipa_ with the arguments it received and returns the result. In the asynchronous method branch, the ASSERT macro uses the state_ == ProxyRunning check expression.

In the Threaded asynchronous branch, proxy_.invokeMethod uses the ConnectionTypeQueued connection type when passing the ThreadProxy method. The {{proxy_name}}Threaded constructor calls ipam->load(). If the call returns false, the constructor returns immediately.

The {{proxy_name}}Threaded constructor calls ipam->createInterface() only if ipam->load() succeeds. If there is no returned pointer, it logs an error containing ipam->path() and returns. If there is a pointer, it converts it to a {{interface_name}} pointer, gives ownership to ipa_, which is unique_ptr, and calls proxy_.setIPA(ipa_.get()). It then connect each interface event to the {{method.mojom_name}}Handler method of the receiver this and sets valid_ to true.

The {{proxy_name}}Isolated constructor uses resolvePath("{{module_name}}_ipa_proxy") to find the worker path. If the path is empty, it logs an error and returns. It then creates IPCPipeUnixSocket(ipam->path().c_str(), proxyWorkerPath.c_str()); if it is not connected, it logs an error and returns. If the connection succeeds, it connects ipc->recv.connect with this as the receiver and &{{proxy_name}}Isolated::recvMessage as the callback, transfers ownership to ipc_ using std::move(ipc), and stores true in valid_.

IPAProxy::resolvePath first checks execPaths_ in order, skipping empty directories, and returns the worker path if it finds one with execute permission. If it finds none, it checks src/libcamera/proxy/worker in the build directory when utils::libcameraBuildPath() is not empty, and checks IPA_PROXY_DIR when it is empty. If the selected path has execute permission, it returns that path; otherwise, it returns an empty string.

IPCPipeUnixSocket::readyRead logs an error and returns if message reception fails or the received data is shorter than IPCMessage::Header. It then looks for a pending entry in callData_ using cookie from the message header. If there is a matching entry, it moves the payload to the corresponding response, marks done as true, and returns.

IPCPipeUnixSocket::sendAsync passes data.payload() to socket_->send. If the return value is nonzero, it logs an error and returns that value unchanged. If the return value is 0, it returns 0.

IPA objects and shutdown order

After successfully calling IPAModule::load() once on a valid module, the caller may call createInterface() for as many IPAInterface instances as needed. The threaded proxy's stop asserts that the state is not ProxyStopping and returns if the state is not ProxyRunning. If it is running, it changes the state to ProxyStopping, calls ThreadProxy::stop with ConnectionTypeBlocking, then stops the thread and waits for it to finish. It then dispatches this proxy's InvokeMessage on the current thread and changes the state to ProxyStopped.

When ipc_ exists, the destructor of the Isolated proxy creates a message with the Exit command and the value of seq_ before it is incremented, and sends it to sendAsync().

Creation and IPC failures

IPAModule::load() returns false if valid_ is false, and returns true if loaded_ is already true. If dlopen fails, it logs an error and returns false. If it cannot find ipaCreate using dlsym, it logs an error, calls dlclose, sets dlHandle_ to nullptr, and returns false. If it finds the symbol, it stores it in ipaCreate_, sets loaded_ to true, and returns true.

IPAModule::createInterface returns nullptr if the module is invalid or not loaded. If both checks pass, it calls ipaCreate_() and returns its return value. IPCPipeUnixSocket::sendSync logs an error and returns the value if the return value of call is nonzero. If the return value is 0, it stores IPCMessage, created as a response, in out when out is present, and then returns 0.

IPCPipeUnixSocket::call inserts an entry into callData_ with cookie as the key and response and false as the values, and uses the result's first as the iterator iter pointing to the entry. This function does not check whether insertion succeeded. It passes message, rather than the iterator, to the socket's send. If sending fails, it erases the entry pointed to by iter using erase and returns the error value returned by send.

If sending succeeds, IPCPipeUnixSocket::call starts the 2000ms timer and loops until the entry's done becomes true. During the loop, if the timer is running, it calls processEvents on the current thread's event dispatcher. If the timer is not running, it erase the entry and returns -ETIMEDOUT. When done becomes true and the loop ends, it erase the entry and returns 0.

template<typename T>
    std::unique_ptr<T> createIPA(const char *name, uint32_t minVersion,
                     uint32_t maxVersion)
    {
        IPAModule *m = module(name, minVersion, maxVersion);
        if (!m)
            return nullptr;

        auto proxy = [&]() -> std::unique_ptr<T> {
            if (isSignatureValid(m))
                return std::make_unique<typename T::Threaded>(m, cm_);
            else
                return std::make_unique<typename T::Isolated>(m, cm_);
        }();

        if (!proxy->isValid()) {
            LOG(IPAManager, Error) << "Failed to load proxy";
            return nullptr;
        }

        return proxy;
    }

bool IPAManager::isSignatureValid([[maybe_unused]] IPAModule *ipa) const
{
#if HAVE_IPA_PUBKEY
    if (forceIsolation_) {
        LOG(IPAManager, Debug)
            << "Isolation of IPA module " << ipa->path()
            << " forced through configuration";
        return false;
    }

    File file{ ipa->path() };
    if (!file.open(File::OpenModeFlag::ReadOnly))
        return false;

    std::span<uint8_t> data = file.map();
    if (data.empty())
        return false;

    bool valid = pubKey_.verify(data, ipa->signature());

    LOG(IPAManager, Debug)
        << "IPA module " << ipa->path() << " signature is "
        << (valid ? "valid" : "not valid");

    return valid;
#else
    return false;
#endif
}

\brief Find a valid full path for a proxy worker for a given executable name
 * \param[in] file File name of proxy worker executable
 *
 * A proxy worker's executable could be found in either the global installation
 * directory, or in the paths specified by the environment variable
 * LIBCAMERA_IPA_PROXY_PATH. This function checks the global install directory
 * first, then LIBCAMERA_IPA_PROXY_PATH in order, and returns the full path to
 * the proxy worker executable that is specified by file. The proxy worker
 * executable shall have exec permission.
 *
 * \return The full path to the proxy worker executable, or an empty string if
 * no valid executable path
 */
std::string IPAProxy::resolvePath(const std::string &file) const
{
    std::string proxyFile = "/" + file;

    /* Try paths from the configuration first. */
    for (const auto &dir : execPaths_) {
        if (dir.empty())
            continue;

        std::string proxyPath = dir + proxyFile;
        if (!access(proxyPath.c_str(), X_OK))
            return proxyPath;
    }

    /*
     * When libcamera is used before it is installed, load proxy workers
     * from the same build directory as the libcamera directory itself.
     * This requires identifying the path of the libcamera.so, and
     * referencing a relative path for the proxy workers from that point.
     */
    std::string root = utils::libcameraBuildPath();
    if (!root.empty()) {
        std::string ipaProxyDir = root + "src/libcamera/proxy/worker";

        LOG(IPAProxy, Info)
            << "libcamera is not installed. Loading proxy workers from '"
            << ipaProxyDir << "'";

        std::string proxyPath = ipaProxyDir + proxyFile;
        if (!access(proxyPath.c_str(), X_OK))
            return proxyPath;

        return std::string();
    }

    /* Else try finding the exec target from the install directory. */
    std::string proxyPath = std::string(IPA_PROXY_DIR) + proxyFile;
    if (!access(proxyPath.c_str(), X_OK))
        return proxyPath;

    return std::string();
}

void IPCPipeUnixSocket::readyRead()
{
    IPCUnixSocket::Payload payload;
    int ret = socket_->receive(&payload);
    if (ret) {
        LOG(IPCPipe, Error) << "Receive message failed" << ret;
        return;
    }

    /* \todo Use span to avoid the double copy when callData is found. */
    if (payload.data.size() < sizeof(IPCMessage::Header)) {
        LOG(IPCPipe, Error) << "Not enough data received";
        return;
    }

    IPCMessage ipcMessage(payload);

    auto callData = callData_.find(ipcMessage.header().cookie);
    if (callData != callData_.end()) {
        *callData->second.response = std::move(payload);
        callData->second.done = true;
        return;
    }

    /* Received unexpected data, this means it's a call from the IPA. */
    recv.emit(ipcMessage);
}

int IPCPipeUnixSocket::call(const IPCUnixSocket::Payload &message,
                IPCUnixSocket::Payload *response, uint32_t cookie)
{
    Timer timeout;
    int ret;

    const auto result = callData_.insert({ cookie, { response, false } });
    const auto &iter = result.first;

    ret = socket_->send(message);
    if (ret) {
        callData_.erase(iter);
        return ret;
    }

    /* \todo Make this less dangerous, see IPCPipe::sendSync() */
    timeout.start(2000ms);
    while (!iter->second.done) {
        if (!timeout.isRunning()) {
            LOG(IPCPipe, Error) << "Call timeout!";
            callData_.erase(iter);
            return -ETIMEDOUT;
        }

        Thread::current()->eventDispatcher()->processEvents();
    }

    callData_.erase(iter);

    return 0;
}

\brief Load the IPA implementation factory from the shared object
 *
 * The IPA module shared object implements an IPAInterface object to be used
 * by pipeline handlers. This function loads the factory function from the
 * shared object. Later, createInterface() can be called to instantiate the
 * IPAInterface.
 *
 * This function only needs to be called successfully once, after which
 * createInterface() can be called as many times as IPAInterface instances are
 * needed.
 *
 * Calling this function on an invalid module (as returned by isValid()) is
 * an error.
 *
 * \return True if load was successful, or already loaded, and false otherwise
 */
bool IPAModule::load()
{
    if (!valid_)
        return false;

    if (loaded_)
        return true;

    dlHandle_ = dlopen(libPath_.c_str(), RTLD_LAZY);
    if (!dlHandle_) {
        LOG(IPAModule, Error)
            << "Failed to open IPA module shared object: "
            << dlerror();
        return false;
    }

    void *symbol = dlsym(dlHandle_, "ipaCreate");
    if (!symbol) {
        LOG(IPAModule, Error)
            << "Failed to load ipaCreate() from IPA module shared object: "
            << dlerror();
        dlclose(dlHandle_);
        dlHandle_ = nullptr;
        return false;
    }

    ipaCreate_ = reinterpret_cast<IPAIntfFactory>(symbol);

    loaded_ = true;

    return true;
}
