    Meanings of the abbreviations and domain terms used in these documents.

    Select an underlined term in the text to see its meaning in place. You can also search for a term by name in Search.

    Shortcuts: 0–9 · A · B · C · D · E · F · G · H · I · L · M · O · P · R · U · V · W · ㄷ · ㅂ · ㅅ · ㅇ · ㅋ · ㅌ · ㅍ · ㅎ

    • 3A: auto exposure (AE, AGC), auto white balance (AWB) and auto focus (AF) together. They are the main algorithms an IPA computes.
    • AF (Auto Focus): the algorithm that moves the lens to bring the image into focus.
    • AGC (Automatic Gain Control): the auto-exposure algorithm that sets exposure time and sensor gain for the scene brightness.
    • ASSERT: libcamera's debug check macro. In debug builds, a false condition logs a fatal message and aborts execution.
    • AWB (Auto White Balance): the algorithm that estimates the colour temperature of the light and sets per-channel R, G and B gains so that white looks white.
    • bayer: a colour filter array where each sensor pixel records only one of R, G or B. Raw data in this format needs debayering before every pixel has RGB values.
    • CCM: means the IPU3 color correction matrix algorithm.
    • DRM (Direct Rendering Manager): A kernel subsystem that manages Linux graphics devices. The DRM pixel format identifies channel layout within a buffer.
    • DW100: a separate hardware device that corrects distortion by remapping the image according to a coordinate table. It is found in the NXP i.MX8MP and others.
    • EBUSY: Calling FrameBufferAllocator::allocate() again on a stream that already has buffers allocated returns -EBUSY.
    • EEXIST: Returns -EEXIST if there is still a fence remaining in the buffer that has not been released, or if a buffer is already registered on the same stream.
    • EGL: An interface that connects the display, image, and buffer of a graphics API and operating environment. This document addresses the boundary for importing shared buffers as graphics images.
    • errno: the standard error numbers Linux functions use to report why they failed. libcamera functions return them as negative values. For example, -ENODEV means no device, -EACCES access denied, -EINVAL an invalid argument, -ENOMEM out of memory and -EXDEV a resource that belongs to another object.
    • ETIMEDOUT: ETIMEDOUT is an error code indicating that a call did not complete because the specified time (2000ms in this file) while waiting for a response during IPC communication was exceeded.
    • FBO: refers to the frame buffer object to which a texture is attached.
    • fence: A synchronization signal indicating when a buffer can be used. A request with a valid fence waits for the signal during preparation. This is different from request completion.
    • FPS: FPS means frames per second.
    • GB: means the green B lens shading correction coefficient.
    • GL: A prefix used for identifiers in the OpenGL family of graphics APIs. The GL format in this document represents the channel composition of a texture.
    • GR: means the green R lens shading correction coefficient in the lens shading correction table.
    • HAL (Hardware Abstraction Layer): the layer that lets an operating system drive different vendors' hardware through one interface. This project ultimately targets an in-house Android Camera HAL.
    • IPA (Image Processing Algorithms): a separate module (.so) holding the image-quality algorithms. It reads the statistics sent by the ISP and computes the ISP settings for the next frame. It is kept apart from libcamera itself so that vendors can ship it without publishing the source.
    • IPC (Inter-Process Communication): message exchange between separate processes. Unsigned IPA modules run in a separate process, so libcamera calls them over IPC.
    • IPU3 (Intel Image Processing Unit 3): the camera ISP in some Intel laptop processors. libcamera has a Pipeline Handler and an IPA for it.
    • ISP (Image Signal Processor): the processing unit that turns the sensor's raw (bayer) data into a usable image. It performs black-level correction, lens shading correction, white balance, debayering and more.
    • LOG: Uses the category and severity level specified by the caller.
    • LSC (Lens Shading Correction): correction for lens shading, where the image edges are darker or tinted compared with the centre because of the lens. It multiplies the image by a correction table laid out as a grid.
    • LUT (Look-Up Table): precomputed results stored in a table and looked up by input value. The LSC correction table is one.
    • mali-c55: the Arm Mali-C55 camera ISP. libcamera has a Pipeline Handler and an IPA for it.
    • mojom: the file format that defines the functions and types of an IPA interface. The proxy code is generated from it at build time.
    • OMM: an external documentation tool whose reading layout and diagram zoom and search rules this site follows. Only the rules were applied; its runner is not used.
    • Pending: A request state that has not yet changed to complete or cancelled. It does not mean device processing has started; an earlier request in this state can delay later returns.
    • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.
    • RKISP1 (Rockchip Image Signal Processor 1): the camera ISP in Rockchip SoCs, the NXP i.MX8MP and others. libcamera has a Pipeline Handler and an IPA for it.
    • UQ: an unsigned fixed-point format. UQ<m, n> represents a value with m integer bits and n fractional bits.
    • UVC (USB Video Class): the standard USB webcams follow. libcamera drives these devices with the uvcvideo Pipeline Handler.
    • V4L2 (Video4Linux2): the Linux kernel API for cameras and video devices. libcamera controls sensors and ISP devices through it.
    • WSL2 (Windows Subsystem for Linux 2): an environment for running Linux on Windows. This site is built from libcamera compiled and extracted in WSL2.
    • Debayering: interpolating each pixel's missing colours from its neighbours to turn bayer raw data into an RGB image. Also called demosaicing.
    • Black level: the baseline value a sensor outputs even with no light at all. It is subtracted in the first stage of ISP processing.
    • Shader: a small program that runs on the GPU. The software ISP can perform debayering and colour correction in GPU shaders.
    • Software ISP: the libcamera component that does ISP processing on the CPU or GPU for devices without a hardware ISP. The source calls it software_isp and softisp.
    • Distortion correction: straightening an image bent by the lens. The RKISP1 pipeline does it by loading a coordinate table (vertex map) into the DW100 device.
    • Control information map: Information describing the controls and ranges available on a camera. The request control list must reference that camera’s information map.
    • Tuning file: a YAML file with per-sensor and per-platform algorithm parameters (correction tables, colour matrices and so on). The IPA reads it at start-up.
    • Proxy: a stand-in object that takes calls through the same interface instead of calling the IPA module directly, and forwards them to the IPA thread or a separate process. It is generated from the mojom definition at build time.
    • Active stream: A Stream associated with the current camera configuration. A request buffer referring to a stream from another configuration is rejected during submission checks.
