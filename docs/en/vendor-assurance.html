Review support conditions and configuration constraints, then define what to validate before product adoption.

Terms in this document: Pipeline Handler, debayer, bayer, ISP
  • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.
  • Debayering: interpolating each pixel's missing colours from its neighbours to turn bayer raw data into an RGB image. Also called demosaicing.
  • bayer: a colour filter array where each sensor pixel records only one of R, G or B. Raw data in this format needs debayering before every pixel has RGB values.
  • ISP (Image Signal Processor): the processing unit that turns the sensor's raw (bayer) data into a usable image. It performs black-level correction, lens shading correction, white balance, debayering and more.

Other terms are in the Glossary.

Support conditions and constraints

CameraConfiguration::Invalid means that the configuration is invalid and cannot be adjusted, and can occur only in extreme cases, such as when the configuration is empty. CameraConfiguration::Adjusted indicates that the configuration has been adjusted and is valid after adjustment. If CameraConfiguration::validate() returns CameraConfiguration::Adjusted, the parameters of any stream may have changed, only some streams' parameters may have changed, and stream configurations may have been removed. When CameraConfiguration::Adjusted, the caller must carefully check the configuration.

If CameraConfiguration::validate() returns CameraConfiguration::Valid, the original configuration was already valid and has not been adjusted. PipelineHandler::generateConfiguration() returns a valid CameraConfiguration if it can satisfy the stream uses requested through roles, and returns a null pointer otherwise. The settings passed to PipelineHandler::configure() are guaranteed to have been validated by CameraConfiguration::validate(), and pipeline handler implementers must not perform additional validation. Implementers of PipelineHandler::configure() must return 0 if configuration succeeds and a negative error code if it fails.

How to interpret performance evidence

The built-in benchmark in DebayerCpu measures only the processing time spent collecting statistics and debayering; it does not include time spent capturing frames or producing output. The built-in benchmark always runs, so it can be used by running cam or qcam on a pipeline that uses Software ISP.
