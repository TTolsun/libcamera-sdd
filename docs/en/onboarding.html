Terms on this page: Pipeline Handler
  • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.

Other terms are in the Glossary.

Reason for separating request submission and completion

The application must populate the request with at least one capture buffer before calling queueRequest. A request without a buffer is invalid and is rejected without being added to the queue. Once a request is queued, the camera signals its completion through the requestCompleted signal.

When a pipeline handler calls completeBuffer to signal completion of the last buffer in a request, the request is not completed automatically. This gives the pipeline handler an opportunity to perform any work that may still be needed, and the handler must explicitly complete the request with completeRequest(). Requests are returned to the application in submission order. The pipeline handler may call completeRequest() for completed requests without ordering constraints.
