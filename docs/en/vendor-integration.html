Review the integration sequence and implementation responsibilities, then apply the configuration, request, and shutdown contracts.

Terms on this page: Pipeline Handler, IPA, proxy, ASSERT
  • Pipeline Handler: the libcamera component that finds a hardware platform's media devices (IPU3, RKISP1 and so on), creates cameras, queues requests to the devices and returns completions. There is one per platform.
  • IPA (Image Processing Algorithms): a separate module (.so) holding the image-quality algorithms. It reads the statistics sent by the ISP and computes the ISP settings for the next frame. It is kept apart from libcamera itself so that vendors can ship it without publishing the source.
  • Proxy: a stand-in object that takes calls through the same interface instead of calling the IPA module directly, and forwards them to the IPA thread or a separate process. It is generated from the mojom definition at build time.
  • ASSERT: libcamera's debug check macro. In debug builds, a false condition logs a fatal message and aborts execution.

Other terms are in the Glossary.

Integration sequence and responsibilities

The application must acquire and configure the camera before it is ready to process requests. After starting the camera, it processes requests until it is stopped; when the application finishes processing requests, it must stop the camera and then release it.

Responsibilities for stopping and handling errors

The PipelineHandler::stop function first calls waitingRequests.swap(data->waitingRequests_) to move pending requests to a temporary store, and then calls stopDevice(camera).

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL367

The Function PipelineHandler::stop must preemptively remove all pending requests that could be requeued due to completeRequest within stopDevice in order to prevent them from being requeued.

Paragraph evidence · 1
  • src/libcamera/pipeline_handler.cppL370 excerpt · Full source L370

Calling the PipelineHandler::stopDevice() Function requires the device implementation to immediately suspend capture and request processing; all remaining requests must be cancelled and completed with an error state.

\brief Retrieve an IPA module that matches a given pipeline handler
 * \param[in] name The IPA module string identifier
 * \param[in] minVersion Minimum acceptable version of IPA module
 * \param[in] maxVersion Maximum acceptable version of IPA module
 */
IPAModule *IPAManager::module(const char *name, uint32_t minVersion,
                  uint32_t maxVersion)
{
    for (const auto &module : modules_) {
        if (module->match(name, minVersion, maxVersion))
            return module.get();
    }

    return nullptr;
}

void PipelineHandler::stop(Camera *camera)
{
    /*
     * Take all waiting requests so that they are not requeued in response
     * to completeRequest() being called inside stopDevice(). Cancel them
     * after the device to keep them in order.
     */
    Camera::Private *data = camera->_d();
    std::queue<Request *> waitingRequests;
    waitingRequests.swap(data->waitingRequests_);

    /* Stop the pipeline handler and let the queued requests complete. */
    stopDevice(camera);

    /* Cancel and signal as complete all waiting requests. */
    while (!waitingRequests.empty()) {
        Request *request = waitingRequests.front();
        waitingRequests.pop();

        /*
         * Cancel all requests by marking them as cancelled and calling
         * doQueueRequest() instead of cancelRequest(). This ensures
         * that the requests get a sequence number and are temporarily
         * added to queuedRequests_ so they can be properly completed in
         * completeRequest().
         */
        request->_d()->cancel();
        doQueueRequest(request);
    }

    /* Make sure no requests are pending. */
    ASSERT(data->queuedRequests_.empty());
    ASSERT(data->waitingRequests_.empty());

    data->requestSequence_ = 0;
}
