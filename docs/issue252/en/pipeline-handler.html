Terms in this document: Pipeline Handler, ASSERT, IPU3
  • Pipeline Handler: A libcamera component that finds the media device of a specific hardware platform (IPU3, RKISP1, etc.), creates cameras, passes requests to the device, and returns their completion. There is one per platform.
  • ASSERT: libcamera's debug-check macro. In debug builds, if the condition is false, it logs a fatal message and aborts execution.
  • IPU3 (Intel Image Processing Unit 3): A camera ISP included in some Intel laptop processors. libcamera has a Pipeline Handler and an IPA for this device.

Other terms can be found in Glossary.

Device matching and object lifetime

PipelineHandler creates and manages Camera by matching the media devices of DeviceEnumerator with supported pipelines, and must be created through PipelineHandlerFactoryBase::create(), never manually. Instances are reference-counted through std::shared_ptr and implement std::enable_shared_from_this to create a new shared_ptr in paths originating from member functions where only this is available. If match() finds all the devices needed for one pipeline, it must acquire all of them with MediaDevice::acquire(), create one or more Camera, store them internally, register them with CameraManager, and then return true. If it fails, match() must either acquire no devices or release all acquired devices with MediaDevice::release(), and return false.

Responsibility for configuration input and validation

The caller of generateConfiguration() must populate roles with a list of stream roles for the use cases for which it wants a default configuration. If the requested roles can be satisfied, generateConfiguration() returns a valid CameraConfiguration; otherwise, generateConfiguration() returns a null pointer. The caller may examine the returned configuration to learn about the selected streams and their default parameters. This function may be called from any thread, must be thread-safe, and must not modify the state of the camera in the pipeline handler.

Stop and incomplete requests

PipelineHandler::stop separates the waiting requests by swapping the camera's waitingRequests_ with a local queue. This prevents the waiting requests from being requeued when completeRequest() is called inside stopDevice(). Immediately after separating them, it calls stopDevice(camera), the device stop function. When stopDevice returns, it removes the separated waiting requests one at a time from the front, marks them as cancelled, and then processes them with doQueueRequest.

The stopDevice implementer must immediately stop capture from all running streams and request processing, cancel incomplete requests already submitted to the device, and immediately complete them in an error state. After stopDevice returns, stop cancels and completes the waiting requests from waitingRequests_ that stop separated beforehand. At the end of stop, ASSERT checks that queuedRequests_ and waitingRequests_ are each empty. The request sequence number requestSequence_ is then reset to 0.

On normal completion, completeRequest calls doQueueRequests at the end. While waitingRequests_ is not empty, doQueueRequests stops the loop if queuedRequests_.size() == maxQueuedRequestsDevice_, and also stops if the first request's prepared_ is false. If neither stopping condition applies, doQueueRequests removes the first request from the queue and passes it on. When stopping, stop first detaches waitingRequests_, so the original waiting requests are not resubmitted even if completion processing is reentered inside stopDevice.

Boundaries of IPU3 Input Size Search

minIfWidth is the larger of the two values in std::max(in.width - ImgUDevice::kIFMaxCropWidth, ImgUDevice::kIFMaxCropWidth). minIfHeight is the larger of the two values in std::max(in.height - ImgUDevice::kIFMaxCropHeight, ImgUDevice::kIFMaxCropHeight).

/**
 * \brief Acquire exclusive access to the pipeline handler for the process
 *
 * This function locks all the media devices used by the pipeline to ensure
 * that no other process can access them concurrently.
 *
 * Access to a pipeline handler may be acquired recursively from within the
 * same process. Every successful acquire() call shall be matched with a
 * release() call. This allows concurrent access to the same pipeline handler
 * from different cameras within the same process.
 *
 * Pipeline handlers shall not call this function directly as the Camera class
 * handles access internally.
 *
 * \context This function is called from the CameraManager thread.
 *
 * \return True if the pipeline handler was acquired, false if another process
 * has already acquired it
 * \sa release()
 */
bool PipelineHandler::acquire(Camera *camera)
{
    if (useCount_ == 0) {
        for (std::shared_ptr<MediaDevice> &media : mediaDevices_) {
            if (!media->lock()) {
                unlockMediaDevices();
                return false;
            }
        }
    }

    if (!acquireDevice(camera)) {
        if (useCount_ == 0)
            unlockMediaDevices();

        return false;
    }

    ++useCount_;
    return true;
}

\brief Stop capturing from all running streams and cancel pending requests
 * \param[in] camera The camera to stop
 *
 * This function stops capturing and processing requests immediately. All
 * pending requests are cancelled and complete immediately in an error state.
 *
 * \context This function is called from the CameraManager thread.
 */
void PipelineHandler::stop(Camera *camera)
{
    /*
     * Take all waiting requests so that they are not requeued in response
     * to completeRequest() being called inside stopDevice(). Cancel them
     * after the device to keep them in order.
     */
    Camera::Private *data = camera->_d();
    std::queue<Request *> waitingRequests;
    waitingRequests.swap(data->waitingRequests_);

    /* Stop the pipeline handler and let the queued requests complete. */
    stopDevice(camera);

    /* Cancel and signal as complete all waiting requests. */
    while (!waitingRequests.empty()) {
        Request *request = waitingRequests.front();
        waitingRequests.pop();

        /*
         * Cancel all requests by marking them as cancelled and calling
         * doQueueRequest() instead of cancelRequest(). This ensures
         * that the requests get a sequence number and are temporarily
         * added to queuedRequests_ so they can be properly completed in
         * completeRequest().
         */
        request->_d()->cancel();
        doQueueRequest(request);
    }

    /* Make sure no requests are pending. */
    ASSERT(data->queuedRequests_.empty());
    ASSERT(data->waitingRequests_.empty());

    data->requestSequence_ = 0;
}

 * \brief Signal request completion

 *
 * The pipeline handler shall call this function to notify the \a camera that
 * the request has completed. The request is no longer managed by the pipeline
 * handler and shall not be accessed once this function returns.
 *

void PipelineHandler::completeRequest(Request *request)

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);

}
