Responsibilities by class

CameraManager is the entry point of libcamera. It enumerates the devices in the system, provides applications with access to cameras, and manages the lifetime of camera objects. Only a single CameraManager instance may exist at a time, and creating an additional instance before deleting the existing instance results in undefined behavior.

The Camera class models a camera that produces one or more image streams from a single image source, and it provides the main interface for configuring and controlling the device and capturing image streams. libcamera manages the lifetime of Camera instances with std::shared_ptr<>. Instances must be created with the create() function, which returns std::shared_ptr. Because the constructors and destructor of Camera are private, instances are prevented from being created or destroyed manually. Request is a frame capture request object that lets applications associate buffers and controls with each frame and queue them for device processing.

The cookie passed to the Request constructor is an opaque value for the application that is stored in the request, and it can be read at any time with the cookie() function.

State and allowed calls

In the state diagram of Camera, acquire() changes the state from Available to Acquired. From the Acquired state, calling configure() transitions to the Configured state, and calling release() transitions to the Available state. An operation that appears in the diagram but has no transition in this state is not allowed, and performing a disallowed operation causes undefined behavior. An operation that does not appear in the diagram at all is allowed in all states.

Errors and termination

Camera::queueRequest() first calls d->isAccessAllowed(Private::CameraRunning). If this result is negative, the value of ret is returned as is. If this result is not negative, the check moves on to the next step. The return branch corresponding to -ENOMEM, as listed in the comment, is not visible in the excerpt body.

If request->_d()->camera() differs from this, queueRequest() logs a LOG message and returns -EXDEV. As the comment states, a request can only be queued to the camera that created it. If request->status() is not equal to Request::RequestPending, the same function logs a LOG message and returns -EINVAL. This check is performed before the controls check.

If request->controls().infoMap() differs from &controls(), the check writes a LOG entry and returns -EINVAL. The log message is Overwriting Request::controls() is not allowed. If request->buffers() is empty, the check returns -EINVAL, and this check is performed before the stream check. Next, for each stream in the request buffers, if it is not in d->activeStreams_, the check returns -EINVAL.

If all the above checks pass, the function pre-processes AeEnable using patchControlList(request->controls()), calls d->pipe_->invokeMethod(&PipelineHandler::queueRequest, ConnectionTypeQueued, request), and returns 0. According to the comment, capture completion is notified through the requestCompleted signal.

Camera::stop() returns 0 without changing state when d->isRunning() is false. If running, the negative result of d->isAccessAllowed(Private::CameraRunning) is returned as is. Therefore, unlike -EACCES in the comment, when not running, 0, not an error, is returned.

If running, change the state to d->setState(Private::CameraStopping), then call d->pipe_->invokeMethod(&PipelineHandler::stop, ConnectionTypeBlocking, this). Next, confirm with ASSERT(!d->pipe_->hasPendingRequests(this)) that no requests are pending, and then Camera::stop returns 0 after d->setState(Private::CameraConfigured). The API comment states that pending requests are cancelled and completed synchronously in an error state, but the cancellation-handling code is not visible in the body of this excerpt.

Concurrency and Execution Checks

The comment on the Camera::createRequest() function specifies that this function is threadsafe. This is a documented guarantee stated in the comment. The excerpted source does not include the function body, so this was not verified from the implementation. The comment on queueRequest states that this function is threadsafe.

The context comment of Camera::start states that calls must be synchronized by the caller with other functions that affect the camera state. The context comment of Camera::stop likewise places the same synchronization obligation on the caller, within the same scope. Therefore, the caller must synchronize calls to start and stop with other functions that affect the camera state.

A pipeline handler that calls completeRequest() must call it from the CameraManager thread. The \context entry of this function specifies the calling thread as the CameraManager thread, and this is a condition the caller must observe. This comment does not specify the thread on which application callbacks are executed. Camera::requestComplete() passes the completed request to requestCompleted.emit(request) and emits the requestCompleted signal.

Disconnection and pending requests

Camera::Private::disconnect() stores the state as CameraConfigured only when state_ is CameraRunning, and skips this store in other states. Separately, disconnected_ is always set to true regardless of the state. According to the comment, the purpose of this handling is to allow applications to free resources and call release() before the camera is deleted.

The two overloads of Camera::Private::isAccessAllowed return -ENODEV before checking the state when both !allowDisconnected and disconnected_ are true. The single state overload returns 0 if currentState equals state, and the range overload returns 0 if currentState is between low and high. Otherwise, the access check logs an error and then returns -EACCES. In the log, from is printed as the calling function name, before () requiring state. In the log, the state name after Camera in is taken from currentState in both overloads, and the required state name is taken from state in the single overload and from low and high in the range overload.

Camera::disconnect() calls _d()->disconnect() first, and then calls disconnected.emit(). Because the two calls execute in the order written in the source, the disconnected signal is emitted after the _d()->disconnect() call completes.

Execution check item: The comment on Camera::disconnect() still has a TODO, "Deal with pending requests if the camera is disconnected in a running state." so handling of pending requests when the connection is lost during running remains a TODO. The excerpted body prints a log with LOG(Camera, Debug), then calls _d()->disconnect() and runs disconnected.emit(). This excerpt shows no code that cancels or completes individual requests. Therefore, this excerpt alone cannot confirm the cancellation or completion behavior of other functions or the results on an actual device.

\brief Queue a request to the camera
 * \param[in] request The request to queue to the camera
 *
 * This function queues a \a request to the camera for capture.
 *
 * After allocating the request with createRequest(), the application shall
 * fill it with at least one capture buffer before queuing it. Requests that
 * contain no buffers are invalid and are rejected without being queued.
 *
 * Once the request has been queued, the camera will notify its completion
 * through the \ref requestCompleted signal.
 *
 * \context This function is \threadsafe. It may only be called when the camera
 * is in the Running state as defined in \ref camera_operation.
 *
 * \return 0 on success or a negative error code otherwise
 * \retval -ENODEV The camera has been disconnected from the system
 * \retval -EACCES The camera is not running so requests can't be queued
 * \retval -EXDEV The request does not belong to this camera
 * \retval -EINVAL The request is invalid
 * \retval -ENOMEM No buffer memory was available to handle the request
 */
int Camera::queueRequest(Request *request)
{
    Private *const d = _d();

    int ret = d->isAccessAllowed(Private::CameraRunning);
    if (ret < 0)
        return ret;

    /* Requests can only be queued to the camera that created them. */
    if (request->_d()->camera() != this) {
        LOG(Camera, Error) << "Request was not created by this camera";
        return -EXDEV;
    }

    if (request->status() != Request::RequestPending) {
        LOG(Camera, Error) << request->toString() << " is not valid";
        return -EINVAL;
    }

    /* Make sure the Request has a valid control list. */
    if (request->controls().infoMap() != &controls()) {
        LOG(Camera, Error) << "Overwriting Request::controls() is not allowed";
        return -EINVAL;
    }

    /*
     * The camera state may change until the end of the function. No locking
     * is however needed as PipelineHandler::queueRequest() will handle
     * this.
     */

    if (request->buffers().empty()) {
        LOG(Camera, Error) << "Request contains no buffers";
        return -EINVAL;
    }

    for (const auto &[stream, buffer] : request->buffers()) {
        if (d->activeStreams_.find(stream) == d->activeStreams_.end()) {
            LOG(Camera, Error) << "Invalid request";
            return -EINVAL;
        }
    }

    /* Pre-process AeEnable. */
    patchControlList(request->controls());

    d->pipe_->invokeMethod(&PipelineHandler::queueRequest,
                   ConnectionTypeQueued, request);

    return 0;
}

     * \todo Make calling stop() when not in 'Running' part of the state
     * machine rather than take this shortcut
     */
    if (!d->isRunning())
        return 0;

    int ret = d->isAccessAllowed(Private::CameraRunning);
    if (ret < 0)
        return ret;

    LOG(Camera, Debug) << "Stopping capture";

    d->setState(Private::CameraStopping);

    d->pipe_->invokeMethod(&PipelineHandler::stop, ConnectionTypeBlocking,
                   this);

    ASSERT(!d->pipe_->hasPendingRequests(this));

    d->setState(Private::CameraConfigured);

    return 0;
}

/**
 * \brief Signal request completion
 * \param[in] request The request that has completed
 *
 * The pipeline handler shall call this function to notify the \a camera that
 * the request has completed. The request is no longer managed by the pipeline
 * handler and shall not be accessed once this function returns.
 *
 * This function ensures that requests will be returned to the application in
 * submission order, the pipeline handler may call it on any complete request
 * without any ordering constraint.
 *
 * \context This function shall be called from the CameraManager thread.
 */
void PipelineHandler::completeRequest(Request *request)
{
    Camera *camera = request->_d()->camera();

    request->_d()->complete();

    Camera::Private *data = camera->_d();

    while (!data->queuedRequests_.empty()) {
        Request *req = data->queuedRequests_.front();
        if (req->status() == Request::RequestPending)
            break;

        ASSERT(!req->hasPendingBuffers());
        data->queuedRequests_.pop_front();
        camera->requestComplete(req);
    }

    /* Allow any waiting requests to be queued to the pipeline. */
    doQueueRequests(camera);
}

 * completeRequest() apply.
 */
void PipelineHandler::cancelRequest(Request *request)
{
    request->_d()->cancel();
    completeRequest(request);

int Camera::Private::isAccessAllowed(State state, bool allowDisconnected,
                     const char *from) const
{
    if (!allowDisconnected && disconnected_)
        return -ENODEV;

    State currentState = state_.load(std::memory_order_acquire);
    if (currentState == state)
        return 0;

    ASSERT(static_cast<unsigned int>(state) < std::size(camera_state_names));

    LOG(Camera, Error) << "Camera in " << camera_state_names[currentState]
               << " state trying " << from << "() requiring state "
               << camera_state_names[state];

    return -EACCES;
}

int Camera::Private::isAccessAllowed(State low, State high,
                     bool allowDisconnected,
                     const char *from) const
{
    if (!allowDisconnected && disconnected_)
        return -ENODEV;

    State currentState = state_.load(std::memory_order_acquire);
    if (currentState >= low && currentState <= high)
        return 0;

    ASSERT(static_cast<unsigned int>(low) < std::size(camera_state_names) &&
           static_cast<unsigned int>(high) < std::size(camera_state_names));

    LOG(Camera, Error) << "Camera in " << camera_state_names[currentState]
               << " state trying " << from
               << "() requiring state between "
               << camera_state_names[low] << " and "
               << camera_state_names[high];

    return -EACCES;
}

void Camera::Private::disconnect()
{
    /*
     * If the camera was running when the hardware was removed force the
     * state to Configured state to allow applications to free resources
     * and call release() before deleting the camera.
     */
    if (state_.load(std::memory_order_acquire) == Private::CameraRunning)
        state_.store(Private::CameraConfigured, std::memory_order_release);

    disconnected_ = true;
}
