이 문서의 용어: V4L2, HAL, Pipeline Handler, IPA 외 1개
  • V4L2 (Video4Linux2): Linux 커널이 카메라와 영상 장치를 다루는 API입니다. libcamera는 이 API로 센서와 ISP 장치를 제어합니다.
  • HAL (Hardware Abstraction Layer): 운영체제가 제조사마다 다른 하드웨어를 같은 인터페이스로 다루게 하는 계층입니다. 이 프로젝트의 최종 적용 대상은 사내 Android Camera HAL입니다.
  • Pipeline Handler: 특정 하드웨어 플랫폼(IPU3, RKISP1 등)의 미디어 장치를 찾아 카메라를 만들고, 요청을 장치에 넣고 완료를 돌려주는 libcamera 구성 요소입니다. 플랫폼마다 하나씩 있습니다.
  • IPA (Image Processing Algorithms): 화질 알고리즘을 담은 별도 모듈(.so)입니다. ISP가 보낸 통계를 보고 다음 프레임에 쓸 ISP 설정값을 계산합니다. 제조사가 소스를 공개하지 않고 제공할 수 있도록 libcamera 본체와 분리되어 있습니다.
  • 3A: 자동 노출(AE·AGC), 자동 화이트 밸런스(AWB), 자동 초점(AF)을 함께 부르는 말입니다. IPA가 계산하는 대표 알고리즘입니다.

다른 용어는 용어집에서 찾을 수 있습니다.

하는 일

libcamera는 Linux, Android, ChromeOS를 대상으로 하는 오픈소스 복잡한 카메라 지원 라이브러리입니다. 이 라이브러리는 Linux kernel device driver와 연동하고, 개발자에게 직관적인 API를 제공합니다. 이를 통해 Linux 시스템에서 복잡한 카메라로 이미지를 캡처하는 과정의 복잡성을 줄입니다.

이러한 드라이버를 이용해 제대로 동작하는 카메라 스택(camera stack)을 구현하는 책임은 userspace에 있습니다. 이 작업은 흔히 vendor마다 따로 구현되며, 응용 프로그램 개발자를 위한 공통 아키텍처나 API가 없습니다. 하드웨어 파이프라인의 차이와 커널 API에서 그 차이가 표현되는 방식 때문에 맞춤형 처리가 자주 필요해지며, 이는 작업에 많은 복잡성을 더합니다.

libcamera는 Linux 기반 시스템을 위한 완전한 카메라 스택(camera stack)을 제공합니다. 이 스택은 카메라에서 원하는 결과를 얻는 데 필요한 하드웨어 설정과 이미지 제어 알고리즘을 추상화(abstract)하고, 커널 API를 통해 이루어지는 이 작업들을 개발자가 쓸 수 있는 단순하고 일관된 방법 하나로 줄여 줍니다.

문단 근거 1개

카메라 스택은 아래에서 위 순서로 네 개의 소프트웨어 계층으로 나뉘며, 가장 아래 계층인 kernel drivers는 카메라 하드웨어를 제어하고 V4L2 계열 API(Media Controller API, V4L2 Video Device API, V4L2 Subdev API)를 통해 낮은 수준의 인터페이스를 userspace에 노출합니다. 그 위의 libcamera framework는 스택의 핵심 부분으로, 카메라 장치의 모든 제어를 담당하고 상위 계층에 네이티브 C++ API를 제공합니다. 세 번째 계층인 libcamera adaptation은 다른 프레임워크와 연결되는 구성 요소를 가리키는 포괄적인 용어이며, 대표 예로 V4L2 호환성 계층, gstreamer libcamera 요소, libcamera 기반 Android 카메라 HAL 구현이 있습니다. 가장 위 계층인 애플리케이션과 상위 수준 프레임워크는 libcamera framework 또는 libcamera adaptation을 기반으로 하며, libcamera 프로젝트의 범위 밖에 있습니다.

받는 것

아래 계층인 kernel drivers는 카메라 하드웨어를 제어하고, Linux 커널의 V4L2 계열 API(Media Controller API, V4L2 Video Device API, V4L2 Subdev API)를 통해 낮은 수준의 인터페이스를 userspace에 노출합니다. 이 구절에는 libcamera가 이 인터페이스를 어떻게 받아 쓰는지가 나와 있지 않으므로, 이 구절만으로는 그 내용을 확정할 수 없습니다.

카메라는 Camera Manager가 열거(enumerate)합니다. Camera Manager는 libcamera가 지원하는 각 카메라를 관리하기 위해 Pipeline Handler를 인스턴스화(instantiate)합니다. Camera Manager 인스턴스는 애플리케이션마다 하나만 실행되며, 한 번에 단일 애플리케이션만 카메라 장치의 제어권을 가질 수 있도록 보장합니다.

내놓는 것

libcamera framework는 스택의 핵심 부분으로, 핵심 구성 요소인 libcamera가 카메라 장치의 모든 제어를 처리하고 상위 계층(upper layers)에 네이티브 C++ API를 제공합니다. libcamera가 노출하는 객체 중 가장 상위 수준의 객체는 Camera 클래스이며, 하나의 카메라 하드웨어 항목을 나타내고 이미지 스트림을 만들 수 있는 기반 장치와 상호작용하는 API를 제공합니다. 같은 하드웨어가 여러 개 연결된 시스템에서는 각 하드웨어가 자신의 Camera 클래스 인스턴스를 가지며, 설정부터 캡처까지 다른 API 작업들이 이 객체와 상호작용합니다.

libcamera adaptation은 다른 프레임워크에서 libcamera에 연결되는 구성 요소들을 가리키는 포괄적인 용어입니다. 대표 예로 V4L2 호환성 계층(V4L2 compatibility layer), gstreamer libcamera 요소, libcamera 기반의 Android 카메라 HAL 구현이 있습니다. 이 구성 요소들은 libcamera 프로젝트의 소스 코드 저장소 안의 별도 저장소에 있을 수 있으며, 예를 들어 gstreamer libcamera 요소처럼 각 프로젝트의 저장소로 옮겨질 수도 있습니다.

다른 팀·계층과의 경계

이 프로젝트의 범위 밖에 있는 것은 애플리케이션과 상위 수준 프레임워크입니다. 이들은 libcamera framework 또는 libcamera adaptation을 기반으로 하지만, libcamera 프로젝트의 범위에는 포함되지 않습니다.

문단 근거 1개
  • Documentation/introduction.rstL163 발췌 · 전체 소스 L163

장치 제조사(vendor)가 기여하는 부분 중 하나는 장치별 Pipeline Handler이며, 이 핸들러는 libcamera 코드 베이스의 일부로서 장치 제조사가 upstream에 기여해야 합니다. IPA 모듈은 3A(Auto-Exposure, Auto-White Balance, Auto-Focus) 등을 구현하는 Image Processing Algorithms(IPA)이며, libcamera 코드 베이스에 포함될 수 있고 카메라 vendor가 외부에서 따로 제공할 수도 있습니다. libcamera에 포함된 IPA 모듈은 자유 소프트웨어 라이선스를 따르며, 외부 IPA 모듈은 오픈소스 또는 비공개 소스가 될 수 있습니다. 제3자는 libcamera 프로젝트의 소스 코드를 포함하지 않는다는 조건에서 비공개 소스 라이선스로 IPA 모듈을 개발하고 배포할 수 있습니다.

The camera stack comprises four software layers. From bottom to top:

* The kernel drivers control the camera hardware and expose a
  low-level interface to userspace through the Linux kernel V4L2
  family of APIs (Media Controller API, V4L2 Video Device API and
  V4L2 Subdev API).

* The libcamera framework is the core part of the stack. It
  handles all control of the camera devices in its core component,
  libcamera, and exposes a native C++ API to upper layers. Optional
  language bindings allow interfacing to libcamera from other
  programming languages.

  Those components live in the same source code repository and
  all together constitute the libcamera framework.

* The libcamera adaptation is an umbrella term designating the
  components that interface to libcamera in other frameworks.
  Notable examples are a V4L2 compatibility layer, a gstreamer
  libcamera element, and an Android camera HAL implementation based
  on libcamera.

  Those components can live in the libcamera project source code
  in separate repositories, or move to their respective project's
  repository (for instance the gstreamer libcamera element).

* The applications and upper level frameworks are based on the
  libcamera framework or libcamera adaptation, and are outside of
