요청을 제출할 캡처 세션을 시작하기

Camera::start()는 카메라 캡처 세션을 시작하며, 선택적으로 controls 목록을 전달할 수 있습니다. 전달된 controls는 카메라를 시작하기 전에 적용됩니다. 시작한 뒤에는 애플리케이션이 요청을 카메라에 큐에 넣어 처리하게 할 수 있으며, 처리된 요청은 애플리케이션으로 반환됩니다. 캡처 세션은 stop()으로 종료될 때까지 이어집니다.

start()는 camera_operation에 정의된 Configured 상태에서만 호출할 수 있습니다. 호출자는 start()를 카메라 상태에 영향을 주는 다른 함수와 동기화해야 합니다. 카메라가 시스템에서 분리된 경우 -ENODEV를 반환하며, 카메라가 시작할 수 있는 상태가 아니면 -EACCES를 반환합니다.

시작 제어값과 파이프라인 결과 반영

Camera::start는 controls가 있으면 ControlList copy(*controls);로 만든 복사본 copy를 patchControlList(copy)로 전처리하고, 이 복사본을 invokeMethod에 전달합니다. controls가 nullptr이면 복사나 전처리 없이 nullptr를 전달합니다. 두 분기 모두 invokeMethod로 PipelineHandler::start를 ConnectionTypeBlocking 연결 타입으로 호출합니다. PipelineHandler::start 문서는 이 함수가 CameraManager 스레드에서 호출되며, 의도된 호출자는 Camera 클래스라고 설명합니다.

Camera::start에서 ret이 0이 아니면 if (ret) return ret;에 따라 ret을 그대로 반환하고 d->setState(Private::CameraRunning)에 도달하지 않습니다. ret이 0이면 d->setState(Private::CameraRunning)을 호출해 CameraRunning 상태로 갱신한 뒤 return 0;에 도달합니다.

ASSERT(d->requestSequence_ == 0);는 isAccessAllowed 검사 블록 뒤, controls 분기 앞에서 실행됩니다. 검사식이 거짓이면 ASSERT는 Fatal 레벨 오류 메시지를 기록하고 프로그램 실행을 중단하며, ret처럼 오류 코드를 반환하는 경로와 다릅니다. log.h를 포함하기 전에 NDEBUG가 정의되어 있으면 ASSERT()는 코드를 생성하지 않습니다.

int Camera::start(const ControlList *controls)
{
    Private *const d = _d();

    int ret = d->isAccessAllowed(Private::CameraConfigured);
    if (ret < 0)
        return ret;

    LOG(Camera, Debug) << "Starting capture";

    ASSERT(d->requestSequence_ == 0);

    if (controls) {
        ControlList copy(*controls);
        patchControlList(copy);
        ret = d->pipe_->invokeMethod(&PipelineHandler::start,
                         ConnectionTypeBlocking, this, &copy);
    } else {
        ret = d->pipe_->invokeMethod(&PipelineHandler::start,
                         ConnectionTypeBlocking, this, nullptr);
    }

    if (ret)
        return ret;

    d->setState(Private::CameraRunning);

    return 0;
}
