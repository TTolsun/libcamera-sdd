# 두 개요의 실제 로컬 Qwen 갱신 기록

Vendor 제품 개요와 Developer 시스템 개요의 설명은 로컬 `qwen3.5:9b`가 작성했습니다. 모델 digest는 `6488c96fa5faab64bb65cbd30d4289e20e6130ef535a93ef9a49f42eda893ea7`입니다. 직접 작성한 설명이나 response-bundle로 두 원고를 대체하지 않았습니다.

## 실행 결과

- 공식 소스: `2c4b67c0792f88f69bcdf9cbf73e81b3d8cf4b6f`.
- 별도 시험 소스의 기본 요청 한도를 32 → 16 → 32로 바꿨습니다. 공식 upstream 변경이 아니며 시험 커밋을 배포 소스로 사용하지 않습니다.
- 각 변경에 운영용 `sdd update`를 실행했습니다. 두 개요의 `queue-limit`만 모델로 다시 생성하고 Vendor 3개, Developer 8개 주제는 유지했습니다.
- 두 변경 소스 모두 실제 WSL 빌드와 전체 300 TU 추출을 수행했고 파싱 오류는 0개였습니다. 첫 변경의 추출 이후 시험 설정에서 빠진 구조 색인 때문에 범위 관문이 중단됐습니다. 색인을 복구한 재시도에는 같은 커밋의 추출 파일을 SHA-256으로 확인해 그대로 재사용했습니다. 복원 커밋은 다시 추출했습니다.
- 복원 트리가 공식 소스 트리와 같음을 확인하고 공식 커밋의 facts·발췌로 재검증했습니다. 공개 원고는 기본값 32를 설명합니다.
- 같은 복원 커밋을 다시 처리했을 때 추가 LLM 호출이 없었습니다.
- `proof.json`의 42개 응답 기록은 단계별 원고에 실제 사용된 로컬 HTTP 응답입니다. 전체 시도 횟수나 모든 실패 응답의 개수를 뜻하지 않습니다.

python qwen-overviews/verify.py qwen-overviews
